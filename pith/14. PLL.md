```c
#define SYSTEM_CORE_CLOCK 72000000
```
이 코드는 실제 프로젝트에서 System core를 하드코딩한 코드이다. 이 매크로 자체는 문제가 없다.

```c
void set_the_hsi_clock() {
    RCC->CFGR &= ~(RCC_CFGR_SW | RCC_CFGR_HPRE | RCC_CFGR_PPRE1 | RCC_CFGR_PPRE2);
    RCC->CFGR |= (RCC_CFGR_SW_HSI | RCC_CFGR_HPRE_DIV1 | RCC_CFGR_PPRE1_DIV1 | RCC_CFGR_PPRE2_DIV1);
    while ((RCC->CFGR & RCC_CFGR_SWS) != RCC_CFGR_SWS_HSI) { }

    return;
}
```
이 코드를 보는 순간 문제가 생긴다. 바로 CORE_CLOCK이 아니고 HSI 소스 클럭으로 세팅하는 것이다. HSI의 소스 클럭은 8MHz이다. 우리는 72MHz를 설정하였으므로, 이에 맞추려면 clock 증폭기인 PLL을 9배를 줘야 한다. 

하지만 최대 관건은 바로 고정 분주 때문에 PLL을 넣을 시 무조건 /2가 된다. 그러므로 우리는 18배를 줘야 하는데, HSI의 최대 상한은 x16이다.
72MHz같은 고클럭은 크리스털 HW가 필요하다. HSI로는 HSE없이 이렇게 높은 클럭을 만들 수 없고, 최대 64MHz가 최대이다.

우리는 72MHz의 절반인 36MHz로 만들 것이다. (정확히 9배)
