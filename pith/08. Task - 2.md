stack은 함수나 지역변수 등이 저장되는 메모리 영역으로, CPU가 현재 stack의 addr을 알기 위해서 사용하는 pointer가 sp이다.

- MSP : Main stack pointer로 CPU가 주로 사용한다.
	- Reset후 해당 pointer를 사용한다.
	- Corterx - m 에서 Handler mode는 항상 MSP를 사용한다.
- PSP : Process stack pointer로 주로 task나 app이 사용한다 
	- task마다 개인 PSP를 가진다.
	- Handler mode를 지원하지 않고, Thread Mode를 지원한다.


=> PSP는 Thread mode, MSP는 Handler mode

---

cortex의 cpu는 크게 두 가지 실행 모드를 가진다.
- Thread mode 
	- 일반 프로그램을 실행
		- main()
		- task1()
	- MSP, PSP 둘 다 사용 가능하다
- Handler mode
	- Interrupt나 Exception Handler를 실행한다.
	- MSP만 사용 가능하다

개념적으로 stack을 두 개의 영역으로 나눌 수는 있는 셈이다.
CONTROL regi를 사용하여 이 Task가 MSP로 가는지 PSP로 가는지 정할 수 있다.

CONTROL.SPSEL
- 0 -> MSP 사용
- 1 -> PSP 사용
- CONTROl.SPSEL = 0 
	=> Thread mode 
		=> MSP 사용 

이는 특수 목적 regi이다. 우리가 특수 목적 regi를 건드리지는 못하기 때문에 cortex개발을 편하게 하기 위해 공통 규격 인터페이스를 제공하는 CMSIS를 사용한다.

우리는 Task mode가 필요하므로, PSP전환을 한다 (CMSIS 사용)
그 후 set_PSP cmsis 함수를 콜해준다. (PSP 전환)

이제 SVC_ Handler 등록을 해줘야 한다. 
일반 Task가 OS에게 요청을 보낼 때 사용하는 Handler이다. 이는 CPU가 Exception을 발생시키게 해준다.

SVC_Handler는 naked 해야한다.
naked 하다
- 컴파일러가 자동으로 SP/regi를 처리하지 않는다
- 코드가 작성한 logic으로 흐르고
- 직접 처리하는 모든 제어권을 가짐

naked하기 때문에 ASM으로 코드를 짜준다. 그 후 Task1 ( = tcb.task_entry)에 기능을 넣어주면
Task1 동작까지 성공이다.
