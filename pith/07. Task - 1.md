---

Task란 실행 중인 프로그램으로, CPU 자원을 소모하는 SW요소이다.  
정확하게는 다른 Task와 CPU를 사용하기 위해 경쟁하는 독립적인 프로그램 실행 단위이다.

Kernel은 System이 시작할 때 System Task를 생성하고 레벨 우선순위를 할당한다. 응용 프로그램에서 생성한 Task에는 System level priority를 사용하면 안 된다. 이는 System 자체에 오류를 범할 수 있는 행위이다. 

System Task
- Init Task
- idel Task
- Logging Task
- Exception Task
- Debug Task

kernel은 기본 초기화와 필요한 Task 생성 후 응용 프로그램 시작 Entry Point로 Jump한다.
이 시점에서 개발자는 응용 프로그램에 필요한 Kernel obj 및 Task 초기화가 가능하다

---

- Task Priority
	- RTOS에서의 Task 우선순위를 의미한다
	- RTOS가 Scheduling을 할 때 사용한다.
	- FreeRTOS는 high Priority의 Ready Task를 실행하는 로직이다.
- System-level Priority
	- Task의 우선순위가 아니다
	- Cortex-M CPU 자체가 Exception/Interrupt를 어떤 순서로 처리할지 결정하는 순서이다

----
Task의 state는 크게 3가지로 나뉜다.
- Ready state : 수행이 가능하지만, 더 높은 우선순위에 밀림
- Block state : 현재 사용 불가한 자원을 요청했거나, 스스로 block 상태로 대기
- running state : 가장 높은 우선순위를 가지며, 실행중

---

태스크는 일반적으로 2개 구조로 나뉜다.
- 끝이 있는 형태
	- Run to Completion Task
	- 응용 프로그램 태스크가 만든 태스크는 다른 태스크보다 우선순위가 높다
	- 응용 프로그램 초기화 태스크는 여러 하위 태스크를 생성하고, 자신을 삭제하거나 block 상태로 바꿈
- 무한 루프 형태
	- Endless Loop Task
	- Endless-Loop Task를 만들 경우 loop 안에 적어도 하나 이상의 blocking 함수가 있어야 한다.
		- pd ms to tick, os.tick 등이 이에 해당한다.

```c
void *stack_init(uint32_t *stack_top, void (*task_enrty)(void)) 
```
구라안치고 이딴 문법을 처음 본다. 아주 간단하게 설명 드간다.

- void * stack_init : 타입 없는 주소 반환
- uint32_t * stack_top : stack top 주소 받기
- void (* task_enrty)(void) : 함수 포인터의 규격이다.
	- 입력 자료형 ( * 함수 이름) (<- 이 함수의 파라미터의 자료형)

xPSR 레지스터는 프로세서의 상태와 실행 흐름을 32bit 안에 포집하는 레지스터이다.
16진수 기준으로 다음 비트는 24bit가 1임을 의미하고, 이는 Thumb 명령으로 동작함을 의미한다.

```
xPSR = 0x1000000
```
LR regi에는 복귀 방식을 명시해야 하는데 
```
0xFFFFFFD
```
이렇게 두면 CPU가 이 LR을 보고 자동으로 Exception return으로 처리한다.
