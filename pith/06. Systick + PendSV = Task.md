### Systick 
Cortex-M 프로세서에 기본으로 들어있는 타이머이다. 
CPU 클럭을 기준으로 일정 주기마다 Interrupt를 발생시킬 수 있다.

![[Pasted image 20260903010647.png]]
Cortex-M3 / M4 기분으로 최소 32Khz 클럭을 가진다.
72MHz는 72,000,000 cycles/sec이다.

Systick을 적절히 설정해서 1ms마다 일으키면 매 틱마다 Interrupt가 발생하고, 이는 보통 OS Tick으로 사용된다.

Task A/B가 프로세스에 해당할 경우에 Systick Handler에서 tick을 증가시킬 수 있다.

### PendSV
나중에 처리하는 이벤트 Exception이다.
Pending Supervisor 

태스크 전환을 안전하게 할 수 있도록 설계된 SW trigger 기반 특수 에외처리이다.
Systick timer ir이나 태스크가 CPU 사용을 원하게 될 때 PendSV에서 비트를 팬딩시키고, 대기한다. 
CPU는 이를 확인하고 ISR같은 중요 작업을 먼저 처리한 후에 중요한 순서대로 PendSV 예외 Task나 요청을 처리한다. 

----

PendSV는 여러개의 Task를 안전하게 Context switching 하는 것인데, 이걸 위해서는 적어도 Task 2개가 필요하다. 그러므로 개발 Pipeline은 다음과 같다.

```
 Systick 설정 -> Task를 위한 메모리 사용 가능 공간 확보 (스택) -> 태스크 생성 -> PendSV -> 테스트
```

----

Systick 정보를 받아와야 한다. 기본 regi, EXTI, NVIC같은 요소는 Datasheet에서 대부분 가져왔지만, 보드 코어 정보는 라이브러리에서도 확인이 가능하다.
```c
core_cm3.h
```
파일을 보면 structure로 나온다.
각 여기에 존재하는 각 구조체 변수들로 값을 조정한다
![[Pasted image 20260904005009.png]]

이렇게 기본 Os_Ticks를 핸들러로 등록했다. 
다만 이 Tick은 단지 시간의 흐름을 알리는 것 뿐이고, Task는 tick 빼고도 많은 요소들로 이뤄진다.

각 Task는 TCB라는 정보를 가진다. TCB는 Kernel이 Task를 알아보기 위한 Metadata라고 생각하면 된다.

대략적으로 아래와 같은 내용을 포함하는 구조체이다.
![[Pasted image 20260904005350.png]]
- task_name : Task 이름
- sp : Stack pointer, 자기가 보유하는 stack mem 주소를 가리키는 regi
- sigs, wati : Task 간 state 주고 받기
	- Link Pointer : TCB를 더블 포인터로 관리하게 해준다

PendSV_Handler나 메모리 초기화 등도 이에 포함한다.
