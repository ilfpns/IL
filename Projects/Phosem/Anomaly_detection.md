### 이상탐지 (Anomaly Detection)

⇒ 전체 데이터 중 특이한 특징을 가지는 데이터를 분류함 

이상탐지에서는 세 단어를 사용한다. 

- x : 입력 데이터
- y : 데이터 라벨
- z : 추출된 특징

    x는 원본 데이터이고 이는 z를 만드는 Encoder (압축 신경망)에 들어간다. 여기서 중요 정보를 압축한 latnet vector가 나온다. 이후 Decoder를 거쳐 다시 복원 x`를 만든다.
    
    두 x의 diff는 x와 x`의 차이이다. 이 diff를 어디서부터 오류로 볼 것 인지 threshold가 정하는 것이고, 이 threshold가 하이퍼파라미터이다.
    

개발자의 상황에 따라서 모델 학습 방식이 달라지고, 이에 따른 성능이 상이하다.

1. Unsupervised Anomaly Detection
    1. 라벨링이 필요 없다. 
    2. 데이터가 부족하고, 불량 발생 시점을 모를 때 사용한다.
    3. 정확도가 뛰어나게 높지 않고, 하이퍼파라미터 값의 영향을 많이 받는다.

1. Semi-supervised Anomaly Detection
    
    이상 데이터의 라벨은 없어도 괜찮다, 하지만 정상 데이터의 라벨은 확실해야한다.
    ⇒ 정상 feature vector만 가짐, 정상에서 벗어난 것을 이상으로 판단.
    
    - One-Class SVM
        - 정상 데이터만 주입하여 정상 데이터가 존재하는 영역의 경계를 찾아냄
        - 새로운 데이터의 Feature가 영역 밖이라면, 이상 판단

1. Supervised Anomaly Detection
    
    정상, 문제 데이터와 라벨을 모두 확실하게 가진다. 데이터의 압도적 불균형이 발생할 시 부족한 파트를 다른 파트의 일부로 치부하는 문제가 발생할 수 있다.
    
    Recall (재현율)을 본다. “실제로 이상인 것 중 얼마나 잡는가?” 하지만 Recall만 보는 상황에서는 threshold에 설정으로 이상한 모델을 만들 수 있다.
    그렇기에 Precision (정밀도) 이상이라고 판단한 것들 중 실제 불량 지표를 함께 본다.
    이 과정에서 AUROC, AURPC를 사용하여 threshold 변환에 따른 전체적인 성능을 볼 수 있다. 
    

---

데이터 특성과 해결하고자 하는 문재애 따라서 사용되는 분류 방법이 달라진다.

1. Outlier detection 
    - 데이터 관점에서 분류한다.
    - 정상 Featrue vector sector에서 벗어난 이미지 Feature를 이상 데이터로 분류
    
    ⇒ 학습에 불량 데이터가 있을 수 있으며, 데이터 Feature 중 특이한 Feature를 가진 데이터를 찾음
    ⇒ 데이터 안에서 본인을 판단
    
2. Novelty detection 
    - 이상치 관점에서 분류한다.
    - 새로운 데이터가 기존 학습 Feature vector sector에서 벗어난 정도를 가지고 새로운 데이터를 분류함
        - 학습에 없는 새로운 유형 분류
    
    ⇒ 학습에 정상 데이터만 있으며, 정상 Bank를 가진다. 새 데이터가 정상 Bank 범위에서 벗어난 정도를 알아낸다.
    ⇒ 새 데이터를 판단

현재 상태 및 진행 게획

Phosem은 2,142 (현재 가진 무결한 데이터)를 모두 Bank를 만드는데 사용하여 Feature vector를 뽑아냄

⇒ Outlier 방식을 사용 (본인 데이터에서 판단)
그러므로 2,142 안에서 불량/정상을 찾는 것에 해당함.

만약 2,142를 모두 정상으로 가정하고 Novelty 방식으로 진행한다면, 이상한 Feature vector가 만들어지고, Bank를 기본으로 성능을 좌우하는 PatchCore의 성능을 좌우할 수 없는 상황이다.

현재 진행 예정 

1. 2,412 장을 가지고 Featrue vector를 뽑아서 Bank로 만들어둔 상
2. 2,412 장에서 Bank를 뽑았으므로, 정확한 라벨 데이터가 있는 1,467장과 채점 ⇒ 이상 탐지 값 얻기 (나중에 새 Bank를 얻을 시 비교)
    - 감안해야 할 것 (한계 가설)
        - 1,467장은 기존 모델로 상위 데이터부터 추린 묶음이다. 그러므로 학습 모델이 더 잘 분리한 좋은 데이터이므로, Feature가 보다 확실하게 구분됨.
        ⇒ 현재 가진 Bank로 점수가 조금 더 높게 나올 수 있음

확인 지표
⇒ 모델이 정상과 이상을 얼마나 잘 구분하는가?

- AUROC : threshold를 하나를 기준으로 하는 것이 아닌, 가능한 모든 threshold를 가지고 정상/불량을 얼마나 잘 분리하는지를 평가하는 지표
    - Model의 Anomaly socre 자체가 정상과 불량의 판단을 제대로 하는가? ⇒ threshold에 관계없이 근본적으로 분류를 제대로 진행함
- AP : 불량 판단 중 실제 불량 비율과, 놓친 실제 불량 비율 평균 지표 ⇒ 불량을 얼마나 잘 잡느냐

제안 방향 (개발 Flow)

1. Outlier 방식으로 첫 분류 진행 ⇒ 불량 의심 사진 제외
2. 분류된 정상 데이터에서 EDA (불량이 없을 것 + 정상 변동을 넓게 덮음) 진행 ⇒ 데이터 질 높이기
3. 정상 데이터만을 가지고 Novelty 방식으로 새 Bank 추출 ⇒ 보다 나은 Bank 뽑기
4. Bank를 가지고 PatchCore 개발
5. 기존 MIL 모델과 합쳐서 지표 내기
    - MIL은 불량의 모양을 학습하였다. 하지만 불량 데이터를 잘못된 라벨링과 부족한 표본 수의 문제를 가졌고, 이를 바탕으로 학습한 MIL은 정확하게 판단하지 못했다.
    - 그렇기에 라벨을 통해 학습한 MIL은 노이즈에 불안정했다. 하지만 라벨 없이 개발된 PatchCore는 정상 Bank와의 거리를 따지기에 이상 데이터 노이즈에 안정적이고, 정상/불량을 기준치만을 가지고 판단한다. (MIL의 문제를 PatchCore가 보완)
    - PatchCore는 ‘문제’와 ‘다름’을 구분하지 못한다. 정상 die지만, 정상 Feature vector와는 다른 Feature가 나올 수 있다. 이것을 라벨을 보고 학습한 MIL이 특징을 비교하여, 정상/불량을 판단한다.
    - 두 모델의 독립적 점수를 합산함 지표 추출

제안 이유는 다음과 같다

- 피드백 소스에는 2,142 데이터를 전부 사용하여 Bank를 뽑을 것을 권장함 ⇒ PatchCore에 Base인 Bank 자체에 불량 데이터가 섥인 문제가 있을 수 있음
- Outlier 방식과 Novelty 방식으로 정상 데이터를 빠르게 모을 수 있다.

참고 사항 

- 이상탐지 구분 방법론에 대해 PatchCore를 사용하는 것은 확정된 것이 아닙니다.
