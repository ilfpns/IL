# 1. Patch 방식 변경

### 1.1 resize 대신 사용된 patch

Patch는 원본 사진을 자른 부분 이미지를 의미한다. 프로젝트에서 800 x 800 이미지를 잘라내어 128px * 128px로 사용하였다.
Crop은 축소가 아닌 사진 그대로 잘라내는 방식이다. resize를 진행하면 작은 정보가 뭉개지기 때문에 이를 방지하기 위해서 작은 patch를 sliding 식으로 검사하기로 계획하였다.

⇒ 적절 Patch size를 찾아야 한다. (검증을 통해 알아볼 예정)

```python
""" 간단한 코드 예제 """
PATCH = 128

 def __getitem__(self, i):
        path, label = self.samples[i]
        img = load_padded(path)
        w, h = img.size
        x = random.randint(0, w - PATCH)
        y = random.randint(0, h - PATCH)
        patch = img.crop((x, y, x + PATCH, y + PATCH))
        return self.tf(patch), label
```

이에 따라 CNN 구성에서 IMG_SIZE를 제거하고, in_size를 사용했다. Patch를 받아 처리하고, output channel도 `[8, 16, 16]`  로 수정했다.

128 * 128 Patch가 입력으로 들어가고, 3 Layer Conv를 통과하면서 MaxPool 방식에 따라 2 * 2 칸에서 최대값만 가지고 가게된다.한 Patch 이미지가 MaxPool을 3회 지나며 feature map이 16 * 16으로 down sampling되고, Flatten으로 4096개를 한 vector로 저장한다. 이를 FC Layer에서 최종 클래스별 점수로 변환한다.

```python
""" 전체 Flow """
128×128 patch (3, 128, 128)
→ Conv1 3×3, 8필터   (8, 128, 128)     # 무늬 감지, 지도 8장
→ BatchNorm + ReLU   (8, 128, 128)     # 값 정리 + 음수 제거
→ MaxPool 2×2        (8, 64, 64)       # 크기 절반
→ Conv2 3×3, 16필터  (16, 64, 64)
→ BatchNorm + ReLU   (16, 64, 64)
→ MaxPool 2×2        (16, 32, 32)
→ Conv3 3×3, 16필터  (16, 32, 32)
→ BatchNorm + ReLU   (16, 32, 32)
→ MaxPool 2×2        (16, 16, 16)      # 최종 feature map: 지도 16장, 각 16×16
→ Flatten            (4096,)           # 16×16×16을 한 줄로 폄
→ FC (Linear)        (클래스 수,)       # 클래스별 점수
→ softmax            (클래스 수,)       # 점수를 확률로 (합=1)
```

## 1.2 분류 체계 변경

기존 분류 체계는 [이물질, 스크래치, 복합]으로만 구분했다. 이는 분류가 세밀하지 못한 단점이 있다. 그렇기 떄문에 ver3에서는 양품 + 불량 12종, 총 13 클래스로 확장하였다. 

- B : Break (끊어짐)

- C : Connect (접합)
- D : Destroy (파손)
- P : Particle (이물질)
- S : Scratch (스크래치)
- B : Break (훼손)

## **1.3 learn & train 이미지 차이**

학습 시에는 die당 무작위 위치에서 patch 8장을 추출해 사용하지만, 검증·실사용 시에는 결함을 놓치지 않도록 die 전체를 빠짐없이 검사해야 한다. 이를 위해 128×128 창을 stride 64(창 크기의 50%)로 이동시키며 800×800 die 한 장에서 patch 144개를 추출한다. 창을 절반씩 겹치게 이동시키는 이유는, 결함이 창 경계에 걸치더라도 반드시 어느 한 창 안에는 온전히 포함되도록 하기 위함이다.

최종 판정은 patch 단위 예측을 die 단위로 집계해 내린다. 144개 patch 각각의 softmax 확률을 평균한 뒤 가장 높은 클래스를 해당 die의 판정 결과로 사용한다. 성능 평가(accuracy, recall, precision, confusion matrix)도 모두 이 die 단위 판정 기준으로 계산한다.

# 3. 결론

### 3.1 느낀점

지난 10일간 다른 일정과 겹쳐 포셈에 온전히 집중하지 못했고, 그만큼 진도가 더뎠다는 점이 먼저 아쉬움으로 남습니다. 하지만 어떤 데이터셋과 모델 구조에서도 성능이 나오지 않는 원인을 찾다가, 결국 문제는 “결함이 찍히지도 않은 patch에 불량 라벨을 붙여 학습”이라는 상황이 있음을 확인했고, 이를 해결하기 위해 MIL 기법을 공부해 적용했습니다. 같은 데이터, 같은 규모의 모델에서 학습 방식 하나를 바꾼 것만으로 붕괴 상태였던 지표가 의미 있는 수준까지 올라온 것은, 병목이 어디에 있는지 찾고 상황에 맞는 기법을 적용하는 것이 중요하다는 것을 배웠습니다.
그럼에도 아직 만족하기는 이르다고 생각합니다. 검증에서 불량 die 17장을 양품으로 놓쳤다는 사실(FN 17)은, 표의 수치가 좋아 보여도 검출 모델의 목적인 불량은 놓치지 않는 것에는 여전히 부족함이 있음을 보여줍니다. 다음 단계에서는 놓친 17장이 어떤 유형이었는지부터 역추적하여, 수치를 올리는 개선이 아니라 놓침을 줄이는 개선에 집중하려 합니다.

### 3.2 향후 계획

현재 분류 체계는 결함의 유형(P/S/D/B/C) 기준이며, 조합 불량은 다중 라벨(예: PSC → P·S·C 세 지표 동시 양성)로 처리해 조합 클래스 폭증 문제를 해소했다. 다음 단계로 검토할 기준은 두 가지다.

1. 크기·훼손 정도 기준의 도입이다. 같은 이물질이라도 크기에 따라 심각도가 다르므로 실용 관점에서는 유형과 심각도의 2축 분류가 이상적이다. 다만 현재 라벨에는 심각도 정보가 없어 모델이 학습할 근거가 없다. 따라서 순서는 
    - 라벨링 단계에서 심각도 등급(예: 경미/중대)을 추가하고, 등급별 손실 가중치 또는 별도 심각도 예측 head를 도입하는 것이다. 라벨 없이 크기를 근사하는 방법으로는, 결함 양성으로 판정된 patch의 개수·분포를 크기 정보로 쓰는 방안을 실험할 수 있다.
2. 심각 불량에 대한 가중치다. 특정 유형(예: 접합부 결함)이 기능상 치명적이라면 두 지점에서 반영할 수 있다. 학습 단계에서는 해당 지표의 loss 가중치(pos_weight)를 높여 민감도를 키우고, 판정 단계에서는 해당 지표의 임계값만 낮춰 recall을 우선한다. 후자는 재학습 없이 적용 가능하므로 먼저 시도한다.

- 향후 계획 → MIL 외 대안 검토
    - 현재 MIL을 선택한 이유는 "결함 위치 라벨이 없다"는 데이터 제약 때문이며, 이 제약이 있을 때 MIL 계열이 합리적이라고 생각하였다.
        - MIL을 주로 사용하지만 다양한 학습 방법을 찾아 사용해볼 예정이다.
- 향후 계획 → threshold 조정의 위치
    - threshold 수정은 근본 해결책이 아니라 마지막 조정 단계임을 실험으로 확인했다. threshold는 이미 학습된 모델의 점수 분포 위에서 recall–precision 트레이드오프 지점을 고르는 것일 뿐, 양품과 불량의 점수 분포가 겹쳐 있으면 어떤 값을 골라도 한쪽을 희생한다.
        - 분포의 겹침 자체를 줄이는 것은 데이터·학습 구조의 몫이며, 실제로 이번 개선에서 성능을 만든 것은 MIL·다중 라벨·ROI였고 threshold는 그 결과를 운영점으로 옮기는 역할이었다.
        또한 현재 검증 불량이 84장뿐이라 에폭마다 최적 threshold가 0.75~0.95로 상이하다는 것을 확인했다. 운영 임계값은 검증 데이터를 늘린 뒤 고정하고, 이후에는 모델이 아니라 요구 recall 수준(예: 불량 recall ≥ 0.95)에서 역산해 결정할 예정이다.
