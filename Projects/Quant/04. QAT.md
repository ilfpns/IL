QAT는 Quantization-Aware Training으로, 학습 과정에서 양자화가 적용될 것을 가정하고, 양자화 효과를 모델이 미리 경험하도록 학습하는 방식이다

PQT와 달리 개발 후 모델에 대한 양자화가 아니다. 이는 빠르고 간단한 경량화가 가능하고, QAT는 양자화로 인한 정확도 손실을 최소화 하는 데에 목적이 있다.

QAT quant flow는 다음과 같다
```
FP32 -> quant 시뮬레이션 -> FP32 가중치 업데이트 -> quant 시뮬레이션 -> FP32 가중치 업데이트 -> ... -> 학습 완료 -> INT8 모델로 변환된 파일
```

실제 학습에서는 fake quantization을 진행한다. 이는 학습에서 양자화 시 발생하는 오차를 학습 과정에 반영하는 것이다.
QAT는 학습 과정에 fake quant를 넣어 양자화 진행 시 생길 벡터 가중치들을 시뮬레이션 하는 것으로, 실제 양자화 모델을 만드는 것 보다 시뮬레이션을 하는 방식이라고 생각할 수 있다.

QAT는 새로운 구조와 모델을 만드는 경량화 기법이 아닌, 양자화를 하면서 이를 개발 과정에 포함하는 학습 방식이다. 그러므로 QAT가 static PTQ보다 빠름을 확인할 수 있다.

---

dynamic은 왜 static보다 작을까? 이는 모델의 크기 영향과 양자화의 특징 요소가 포함된 결과이다.

1. 양자화는 다시 복원될 수 있다. 여기에 zero-point/scale이 쓰인다. static은 이 정보를 가지고있어야 활성화를 조정할 수 있다. 하지만 dynamic은 실행 중에 calibration value (scale/zero-point)를 얻기에 이런 부가 데이터를 따로 저장하는 양이 적기에, dynamic의 전체 크기가 더 작은 것이다.
2. 1번에 영향은 막 엄청 크지 않다. MLP같은 작은 모델을 사용했기에, 그 차이가 분명한 것이다.

정리하면 Dynamic PTQ가 Static PTQ보다 약간 작은 이유는 activation의 양자화 파라미터를 추론 시 동적으로 계산하기 때문이다. 반면 Static PTQ는 activation 양자화를 위해 미리 결정된 양자화 정보를 사용한다. 다만 이 차이는 크지 않으며, 작은 MLP에서는 모델 자체의 weight 크기가 작아 이러한 부가 정보의 차이가 상대적으로 크게 나타난다고 할 수 있다.

---

세 모델 모두 일반 FP32보다 느려진 것을 볼 수 있다. 어째서 또 이렇게 된걸까? 
이는 어제와 같은 이유이다. 모델 규모가 작은 MLP에서 INT8 연산 자체의 이점보다 quantization/dequantization 및 연산 커널 호출 등의 오버헤드가 상대적으로 크게 작용했기 때문으로 해석할 수 있다.

어제와 같은 결론이 나온다고 모델 크기 감소가 절대적 추론 속도 증가를 야기하지 않는다.
양자화를 진행하며 생기는 overhead도 무시할 수 없는 것이다. static도 사전 변환 과정이 있지만, FP32와 INT8 데이터 변환에 시간을 쓰지 않는 건 아니라는 것이다.

---

동적으로 양자화를 하는 dynamic이 가장 오래 걸린 것은 당연하다
```
Dynamic > static ptq > qat > FP32
```
커널 구조가 조금씩 다르기에 값이 다르지만 static ptq = qat의 추론 속도를 보여주는 것이 이상적 기대 값이다.

```

```
Output diff는 QAT가 처참한 것을 볼 수 있다. 동적 활성화 양자화 파라미터를 계산하는 dynamic이 가장 기존 값 보존을 잘 했다. 

QAT는 FP32 모델의 성능을 최대한 유지한다. 근데 기존 모델을 보존하는 것이라면 output diff가 비슷해야하는데, 왜 이럴까?

이렇게 된 원인은 여러가지로 뽑을 수 있다.
- QAT 학습이 부족함
	- 중간중간 fake quantization 보정값을 넣어 학습해야하는데, 그렇지 못했다.
- 학습률/epoch 등의 설정 문제
- QAT 모델이 충분히 수렴하지 않는다


정리하면 이번 실험에서는 Dynamic PTQ가 FP32 출력과 가장 작은 최대 출력 차이를 보였으며, Static PTQ와 QAT 순으로 차이가 증가했다. 다만 QAT의 목적은 FP32 출력 자체를 최대한 동일하게 유지하는 것이 아니라, 양자화 환경에서 모델의 task 성능을 유지하도록 학습하는 것이므로 Max Output Diff만으로 QAT의 성능을 판단할 수 없다.

Task는 model이 수행하는 일을 의미한다. 
task 성능 유지 = model이 해야하는 일에 대한 성능 유디
ex) yolo의 task = image detection
