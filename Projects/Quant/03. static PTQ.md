static은 dynamic과 달리 가중치 (고정된 부분)만 양자화를 진행한다

static quantization역시 calibration이 필요하다. 이전에 개념 학습을 잘못해서 dynamic과 static의 차이를 잘못 인지했다.

static과 dynamic 모두 가중치와 활성화를 양자화 한다. 차이는 dynamic은 static과 달리 활성화를 실시간으로 양자화하는 것이다. static은 사전에 구한 cali만을 가지고 가중치 + 활성화 전부 양자화한다. 고로 dynamic은 cali가 필요 없다. (즉시 구하면 됨)

PTQ 방식의 static quant는 calibration을 통해 활성화의 int8 범위에 현재 값을 어떻게 매핑할 것인지 정교하게 정하기 때문이다. 이렇게 원래 사이즈 정보에서 더 작은 사이즈로 옮기는 시점에도 정보를 소실하지 않는다.

이제 결과를 보자

----
```
===== Model Size / Structure =====

[FP32]
State dict size: 0.138 MB

[Dynamic PTQ (INT8)]
State dict size: 0.039 MB

[Static PTQ (INT8)]
State dict size: 0.044 MB

===== Inference Speed Comparison =====
Label                    Latency(ms)   Speedup     MaxDiff
----------------------------------------------------------
FP32                          0.0772     1.00x           -
Dynamic PTQ                   0.4016     0.19x    0.005642
Static PTQ                    0.3576     0.22x    0.069035
=======================================

===== Max Output Diff vs FP32 =====
Dynamic PTQ           : 0.005642
Static PTQ            : 0.069035
====================================
```
이렇게 결과가 나왔다. 

0.38 size MLP 모델 size를
- dynamic : 0.039
- static : 0.044
로 줄여냈다. 

---

Max Output Diff는 실행 시 활성화 양자화 파라미터를 (양자화를 진행하는)결정하는 dynamic이 원본 출력값을 static보다 더 가깝게 보존했다.

---

dynamic은 왜 static보다 작게 경량화되었을까?
=> Dynamic이 Static보다 작게 저장된 것은 calibration 때문이 아니다. Calibration은 Static PTQ의 activation quantization parameter를 결정하는 과정이며, 이번 실험에서는 주로 Max Output Diff에 영향을 준다. 크기 차이는 PyTorch에서 Dynamic/Static 양자화 모델을 서로 다른 방식으로 표현하고 저장하면서 발생한 state_dict의 구조 및 quantization metadata 차이로 볼 수 있다.

1장에서 말했듯, 프레임워크에 따라 경량화되는 크기가 달라지고, 이번에는 그 크기가 누적되어 dynamic이 더 작아지게 했을 것이다.
이는 일반적인 특성이 아니다.

---

static이 dynamic보다 더 빠르게 측정된 것을 알 수 있다.
dynamic은 static과 달리 실행하며 활성화 양자화를 하기에 overhead가 크다. 그렇기에 양자화 전 모델보다 속도가 느려짐을 알 수 있다. 물론 static도 overhead가 작용한다. 이는 모델의 크기가 크지 않아서 더 두드러지게 보인다. (모델 연산보다 양자화 overhead가 걸림)

양자화의 이득보다 overhead가 더 큰 상황이다.

이전에 말한 Linear와 Conv의 차이도 여기서 볼 수 있다. 하여 경량화의 차이를 눈에 띄게 보기 쉽지 않다.
Conv는 동일한 convolution kernel(weight)을 여러 공간적 위치에서 반복적으로 사용하기 때문에 weight reuse (가중치 재사용률)가 높고 cache locality (캐시 지역성)가 좋은 편이다.

이러한 결과는 이전에 살펴본 Linear와 Conv의 연산 특성을 이해하는 데에도 연결해서 볼 수 있다. 다만 이번 실험은 MLP를 대상으로 했기 때문에 Conv의 locality 효과를 직접 검증한 결과는 아니다.

더 빠른 모델은 단순 양자화가 아닌 
- CPU의 INT8 지원
- VNNI 명령어 지원
- 모델 크기
- 연산 종류
- Cache locality
- 등으로 정해지게 된다.

---

이번 학습으로 작은 MLP에서는 INT8로 weight를 줄였음에도, 메모리 절약에 따른 이득보다 quantization/runtime overhead가 더 크게 나타나 속도 향상으로 이어지지 않았다는 것을 배웟다.
