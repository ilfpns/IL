ONNX runtime은 MS가 개발한 오픈소스 ML 추론 엔진이다. 이는 다양한 AI framework에서 내보낸 모델을 .onnx api 하나로 단일 실행할 수 있다. 

ONNX는 특정 framework의 전용 모델이 아닌, 연산자 표준에 기반한 중간 IR이다. 각 연산자는 ONNX 표준 연산자 집합으로 정의된다. 이때 opset은 사용 가능한 연산자 버전 묶음을 의미한다. 해당 opset이 맞아야 모델을 실행할 수 있다.

---
더욱 자세한 이해를 위해서 조금 더 알아보자

IR은 중간 계층을 의미한다. 예를 들어 Pytorch 모델을 Jetson에서 그대로 실행하는 것이 아닌. ONNX가 Pytorch와 TensorRT 사이에서 모델을 표현하는 중간 계층 형태로 나타나는 것이다.

AI는 결국 특정 연산의 집합이다. 최근에 개발한 CNN도
```
Input -> Conv -> ReLU -> MaxPool -> MatmMul -> SoftMax -> Output
```
형태였다. 여기서 각 단계를 연산(OP) 라고 한다.

Pytorch는 본인의 OP로, Tensor는 본인의 OP로 이를 정의하므로 둘이 호환이 안 된다. ONNX는 모델에서 사용하는 OP의 기본 인터페이스를 따로 정의하여, 서로 다른 규격의 OP가 사용되지 않도록 한다. 

여기서 OP의 집합을 opset이라 한다. opset은 시간에 따라 바뀌는 OP의 정의, 사용 공식을 버전으로 표기한 것이다.
```
Opset 10
 - Conv v1
```
위 Conv v1은 opset 10기준으로 만들어진 것이다.
ONNX는 OP뿐 아니라 전체 계산 그래프 자체를 ONNX 형식으로 변환한다.

---

OP는 Node와 다른 개념이다
- OP : 연산의 정의
- opset : OP의 사용 기준 정리
- Node : 실제 그래프 연산 인스턴스
	- OP를 실제 모델 그래프에 배치한 것

---

ONNX는 실행 엔진이 아니다. 
ONNX는 각 모델을 표현하고 인터페이스에 맞게 전달하는 것이다. 이 자체가 GPU에서 빠르게 실행해주는 엔진은 아니다. 

그렇기에 보통 다음과 같은 개발 flow를 가진다
```
pytorch 학습 -> ONNX 변환 -> TensorRT 최적회 -> CUDA GPU)
```
여기서 ONNX 변환과 TensorRT 사이에 OP 규격이 무조건 항상 맞다고 장담할 수 없다.

---

결정적으로 ONNX는 프레임워크와 실행 환경을 분리할 수 있다. 
과거에는 Pytorch모델에서 학습하고, 같은 환경에서 실행했다면, 현재에는 ONNX를 IR로 두고 Pytorch로 모델 개발 후 TensorRT로 최적화를 할 수 있는 것이다.

---

ONNX runtime은 모델을 실제로 실행해 주는 환경으로 ONNX가 IR로써 역할을 하고 각 OP의 규격을 맞추고 실행과 프레임워크 환경을 정했다면, ONNX runtime으로 ONNX 모델을 실행할 수 있는 것이다.
