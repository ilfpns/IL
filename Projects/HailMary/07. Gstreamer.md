Gstreamer를 편의상 gst라고 지칭하겠다. 

gst는 영상, 스트림 데이터, 오디오 등을 멀티미디어 프레임워크이다. 다양한 데이터 프로토콜로 파이프라인을 구상할 수 있게 해준다. 

같은 멀티미디어 프레임워크인 FFmpeg와 어떤 차이점을 가질까?
- FFmpeg : 미디어를 처리하는 tools/lib
- Gstreamer : 미디어 처리 과정을 연결해서 구성하는 파이프라인 프레임워크

즉 FFmpeg는 OpenCV처럼 인풋에 대한 처리 후 아웃풋을 내는 도구이고, Gst는 이를 이어서 데이터 흐름을 만드는 파이프라인 생성 프레임워크인 것이다.

---

gst는 다음 구조로 이해할 수 있다.
```
Source -> Processing -> Sink 
```
이 Pipeline은 멀티미디어 데이터를 처리하는 일련의 element로 이뤄진다.
각 element는 입력 (source)와 출력 (sink)로 이뤄진다. 

```
Camera
  ↓
nvarguscamerasrc
  ↓
nvvidconv
  ↓
nvv4l2h264enc
  ↓
h264parse
  ↓
qtmux
  ↓
filesink
```
각 element가 자기 역할을 하고, pad를 통해 서로 연결된다

---

Element는 파이프라인을 구성하는 추상화된 block형태를 정의한다. 특정 source와 이에 맞는 sink를 내놓는 black box라고 볼 수 있다.

plug와 port같은 개념으로 각 element의 src와 sink를 잇는 연결 요소를 pad라고 한다.

Bins는 모여있는 Element의 컨테이너 단위이다. elements 자체의 서브클래스 개념이며, Elements들의 복잡성을 추상화할 수 있다. Bins 자체의 state를 바꿈으로서 그 안에 Elements의 state도 바꿀 수 있다.

Pipeline은 Bins를 전보 포함하는 최상위 Bins로 통한다. 이는 전체 프로그램 버스를 제공하고, 자식 bins에 대한 동기화 관리를 진행한다. 

---

또한 통신 방식은 크게 4가지로 나뉜다.
- buffer : pipeline 요소 간 데이터 전달 객체로 src -> sink의 이동 객체
- event : element 간 또는 응용 프로그램에서 element로 전송되는 객체가 이동하는 객체
- message : pipeline에서 element별로 게시된 객체, 응용 프로그램에서 수집을 위해 유지한다.
- query :  응용 프로그램은 query를 통해 pipeline에서 지속 시간, 현재 재생 위치 같은 정보를 확인할 수 있다.
