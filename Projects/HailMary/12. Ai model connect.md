Judge Element는 AI Element의 sink을 src로 받는다. AI element의 process method는 sink로 여러 판단 정보 structure를 내보낸다.
```
{ 
	int x;  
	int y;  
	int width;  
	int height;  
	float score;
}
```

AI는 결과를 Judge와 연결된 Pad buffer로 넘긴다. 해당 Metadata를 넘기는 API는 Gst가 지원한다. Pad buffer을 검사하는 Probe이 존재한다.

Probe은 Pad를 지나가는 data를 검사한다. Probe 로직은 다음과 같이 동작한다. Probe은 C는 호출 불가한 Callback을 호출한다.

이는 불량/정상 로직을 해결하며, Frame과 metadata를 C++로 바꾼다.

----

AI, Judge element는 identity의 factory name을 사용한다. 

identity는 데이터를 변경하지 않고, 그대로 통과시키는 디버깅/관찰 전용 element이다. 
AI element는 sink로 BBox 정형 data를 보내고, Judge는 src로 이를 받아서 판단한다.

Judge의 process는 문제 판단 시 snapshot method로 처리한다.

----

이제 실제 Camera의 src를 OpenCV와 잇고, Judge의 sink structure를 정해야 한다.

- Camera element와 OpenCV 연결 protocol : tcp loopback
	- tcp loopback
		- TCP 
		- TCP는 기기 간 신뢰성 있는 데이터 전송 프로토콜이다. 이는 연결 과정에서 3-way handshake를 통해 연결 보호하여 신뢰성을 가지는 프로토콜이다.
		- data 통신 간 ack (긍정 수신) 과정을 통해 데이터 유실을 최소화하고, 이는 QoS를 통해 설정할 수 있다.
	- tcp loopback은 기기 간 통신이 아닌, local tcp 통신을 의미한다. local 네트워크 (같은 네트워크)로 통신하므로 OS 내부 network stack에서 처리한다.
	- local network 방식에서도 3-way handshake 방식을 가진다.
