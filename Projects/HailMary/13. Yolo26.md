> [!info]- 회고
> 
> 지금까지 나는 임베디드를 공부하며 임베디드 개발 방식에 익숙해져 있었다.
> ```
> 보드 비교 -> 보드 선정 -> Framework 선정 -> Framework 공부 -> 프로토콜 비교 및 선정 -> 아키텍쳐 설계 -> Pipeline 설계 -> 세부 로직 구현 -> 테스트 -> ...
> ```
> 이러한 방식은 임베디드에서 가능했고, 효과적이었다. 
> 
> 1. 비교를 통해 몰랐던 사실을 배울 수 있음 
> 2. 이러한 과정으로 정답을 찾고, 정답에 맞춰 개발할 수 있음
> 이러한 방법이 가능했던 이유는, 내가 임베디드에 대한 배경 지식이 있기 떄문이다.
> 
> - 어떤 것이 중요한가?
> - 어떤 것을 보아야 하는가?
> - 어떤 것을 비교해야 하는가?
> - 어떤 것이 대표적인가?
> - 어떤 것을 기준으로 잡아야 하는가?
> 이런 것들은 배경지식에서 나오는 것이었다.
> 
> 하지만 최근 개발하는 AI는 그렇지 않았다. 기술적 배경 지식이 없었다. 그렇기에 비교할 수 없고, 선택할 수 없었다.
> 애초에 비교를 고려하지도 않았다. 단지 AI가 가장 먼저 추천하는 것을 기용하고, 개발했다.
> 
> 이런 문제를 느끼고, 개발 스타일을 바꿔보려 한다.
> .
> 1. 배경 조사
> 	- 어떤 것이 좋고, 어떤 것이 나쁜지 확실한 배경 조사는 필수적인 과정이다.
> 2. 배경 공부
> 	- 단지 AI에게 여러 제안을 받고, 단순하게 고르는 것이 아닌, 그 기술적 이유까지 공부하고, 내가 직접 판단한다.
> 3. AI 의존
> 	- AI가 많은 일을 해주지만, 모든 것을 의존하는 것은 절대로 안된다.
> 		- Arch를 따르는 구조 설계
> 		- Pipeline을 따르는 데이터 흐름
> 		- 설정한 분기 점프
> 	 등 필요한 것을 직접 보고, 개발하고, 판단한다.

기존에는 AI가 추천해준 Yolo8을 사용했다. 이는 2023년에 개발된 모델로 현재 최신 모델 Yolo26과 많은 기능적/성능적 차이가 나는 모델이다. 두 모델에 대해 공부하고 새로운 AI 모델 학습을 진행하고자 한다.

| 항목                    | 확인할 것                                                                                         |
| --------------------- | --------------------------------------------------------------------------------------------- |
| **Seed 고정**           | 두 번 실행했을 때 동일한 결과가 나와야 한다.                                                                    |
| **단순화**               | 데이터 증강을 끈다. 지금은 버그가 들어올 가능성만 늘릴 수 있다.                                                         |
| **평가 정밀도**            | 전체 테스트셋으로 평가하고, 배치 loss 스무딩에 의존하지 않는다.                                                        |
| **초기 Loss 확인**        | Softmax 분류라면 초기 loss는 `-log(1 / 클래스 수)`에 가까워야 한다.                                             |
| **초기화**               | 마지막 층의 bias를 타깃 평균 또는 클래스 비율에 맞춘다. 불필요한 초기 loss를 제거한다.                                        |
| **사람 베이스라인**          | 사람이 직접 정확도를 측정하거나, 테스트셋을 두 번 라벨링하여 라벨 일치도를 확인한다.                                              |
| **입력 무관 베이스라인**       | 입력을 0으로 바꿔 학습한다. 실제 데이터보다 성능이 나빠야 정상이다.                                                       |
| **1배치 과적합**           | 2~몇 개의 샘플만 사용해 loss를 바닥까지 낮춘다. 라벨과 예측이 완전히 일치해야 한다.                                           |
| **Train Loss 감소**     | 모델 용량을 조금 늘렸을 때 Train Loss가 감소하는지 확인한다.                                                       |
| **네트워크 직전 시각화**       | `y_hat = model(x)` 직전의 텐서를 디코딩해서 확인한다. 모델이 실제로 받는 입력이 가장 중요한 기준이다.                            |
| **예측 동역학**            | 고정된 배치의 예측값이 학습 과정에서 어떻게 변화하는지 확인한다.                                                          |
| **Backprop으로 의존성 확인** | Loss를 샘플 `i`의 출력 합으로 설정하고, `i`번째 입력에만 Gradient가 발생하는지 확인한다. `view`/`permute` 관련 버그를 탐지할 수 있다. |
| **특수 → 일반**           | 먼저 루프 버전을 구현하고 정상 동작을 확인한 뒤 벡터화한다.                                                            |


> [!info]- 과적합 (overfit)
> ML 학습에서 가장 무서운 단계이다.
> 
> 먼저 과적합이 날 정도로 큰 모델을 준비한다. 예를 들면 resnet, transformer 모델이 해당할 것이다. 이러한 모델로 먼저 데이터를 사전학습 시킨다. 
> 
> 만약 데이터가 100장이라면, 거의 100%에 수렴하는 판단률을 보여야 한다. 그렇지 못한 것은 데이터 자체의 문제로 판단할 수 있다. 
> 그 다음으로 정규화를 진행해야 한다. 큰 모델에서 점점 규제를 추가하며 일반 모델로 만드는 것이다.
> 
> 작은 모델로 기능을 추가하며 학습 시 어떤 부분이 에러 원인인지 파악할 수 없다.
> 
> - LR로 시작하고 Decay를 마지막에 튜닝해라
> 	- learning late (학습률)은 가중치를 얼마나 크게 바꿀지 정하는 값이다.
> 	- 상수 LR로 시작해서 점점 LR 값을 줄이는 기법이다 (decay)
> 	- LR을 고정하고, 마지막에 decay를 튜닝한다.
> 		- decay마다 재학습을 하지 않기 위해서 체크포인트를 만들 수 있다.
> 		- 이렇게 가중치 변화량을 조절한다.
> - Adam 3e-4는 안전하다.
> 	- 옵티마이저를 정하는데, LR을 0.0003으로 사용한다는 것이다.
> 	- 옵티마이저는 Loss를 줄이기 위해 모델 가중치 업데이트를 어떻게 할지 결정하는 알고리즘이다.

다음 과정은 정규화이다. 다음은 카파시가 제안한 정규화 Flow이다.

1. **실제 데이터를 더 모은다.** 잘 설정된 네트워크를 거의 확실하게 개선하는 유일한 방법이다.
2. **데이터 증강** (반쯤 가짜 데이터)
3. **창의적 증강:** 도메인 랜덤화, 시뮬레이션, 장면에 합성 삽입, GAN
4. **사전학습:** 데이터가 충분해도 거의 손해가 없다.
5. 지도학습을 고수한다 (2019년 의견, 아래 업데이트 참고)
6. **입력 차원 축소:** 허위 신호가 있을 만한 특징을 뺀다.
7. **모델 축소:** 도메인 지식으로 줄인다 (예: FC 층을 average pooling으로 교체).
8. **배치 크기 축소:** BN 통계의 노이즈가 정규화 효과를 낸다.
9. **dropout:** ConvNet은 dropout2d. BN과 궁합이 나쁘니 조심해서 쓴다.
10. **weight decay** 증가
11. **early stopping**
12. **더 큰 모델 + early stopping:** 작은 모델보다 오히려 나을 때가 있다.

CNN 기반 AI가 첫 Conv Layer에서 이미지를 보고 어떤 특징을 잡아내는지 눈으로 보는 것이다. 필터를 시각화 하고, 다음과 같은 증상이 있다면 뭔가 잘못된 것이다.

- 깔끔하지 않게 발생한 노이즈
- 매 필터가 비슷한 생김새 보유
- 어딘가로 몰린 특징

"데이터와 하나 되기"단계에서 찾은 data의 부족한 부분을 채울 데이터를 더 몹는다. 

> [!info]- 튜닝
> 신경망은 일부 파라미터에 대해 예민하다. 그렇기 때문에 중요한 파라미터에 대한 검색 값이 높은 랜덤 서치보다. 그리드 방식은 중요하지 않은 파라미터를 반복해서 보기 때문에 자원 낭비일 수 있다.

> - 그리드 서치 : 가능한 조합을 전부 시험
> 	- 체계적
> 	- 확습 횟수 많음
> - 랜덤 서치 : 정해진 범위 내에서 조합을 랜덤하게 뽑아서 시험

> [!info]- 짜내기
> 카파시는 두 방법을 제시한다.
> 	1. 앙상블 사용
> 		- 여러 개의 모델을 학습시켜서 예측을 합치는 것이다.
> 			1. 서로 다른 아키텍쳐의 모델로 앙상블을 만들 수 있다.
> 			2. 같은 아키텍쳐의 모델에서 서로 다른 학습 결과를 가지는 모델을 합쳐 앙상블을 만들 수 있다.
> 		- HW 자원이 부족하다면, 지식 증류의 단일 네트워크를 사용할 수 있다.
> 			- 앙상블은 여러 개의 모델 조합이기에, 추론 시 여러 모델을 돌리는 부담이 있다.
> 			- 반면 지식 증류는 앙상블같이 여러 모델의 지식을 하나의 작은 student 모델로 옮겨서 하나만 실행하는 것이다.
> 			- 즉 앙상블의 성능 향상은 얻고 싶지만, 여러 모델을 동시에 돌리는 것이 힘들다면, 앙상블 모델들의 지식을 하나로 모아서 자식 student model 하나로 사용하는 것을 고려할 수 있다.
> 	2. 오랜 학습
> 		- 평평해 보이는 val loss도 계속 진전이 있는 것이다
> 
> TTA 같은 방식도 사용할 수 있다.
> - 추론 시 데이터를 여러 방식으로 변형해서 예측하는 것
> 	- 기존에는 원본 이미지를 모델이 예측하는 것이다.
> 	- TTA 적용 시 원본 이미지를 
> 		- 원본
> 		- 좌우 반전
> 		- 다른 크기
> 		- Crop
> 		등을 적용해서 여러 번 추론하고 결과를 합치는 것을 말한다. 같은 이미지 다른 입력 방식에서 값이 다를 수 있다. 이것을 방지하기 위해 여러 입력에 대한 예측 값을 합쳐, 안정정인 값을 얻는 방식이다.
>

본격적인 Yolo8과 Yolo26 비교를 해보자.

| 항목 | YOLOv8 (2023.01) | YOLO26 (2026.01) |
|---|---|---|
| **후처리** | NMS 필요 | NMS 없음 (End-to-End) |
| **박스 회귀** | DFL (분포 기반, Softmax 포함) | DFL 제거, 직접 회귀 |
| **라벨 할당** | TAL, 객체당 여러 Positive | 1:1 할당 + STAL |
| **Loss 가중치** | 고정 | ProgLoss |
| **옵티마이저** | SGD / AdamW | MuSGD |
| **라이선스** | AGPL-3.0 | AGPL-3.0 |
- NMS 추가 : 한 객체에 여러 BBox 생성 시 가장 높은 확률 선택

| 모델 | mAP50-95 | CPU ONNX | T4 TensorRT | 파라미터 |
|---|---:|---:|---:|---:|
| v8n → 26n | 37.3 → **40.9** | 80.4 → **38.9** ms | **1.47** → 1.7 ms | 3.2 → 2.4M |
| v8s → 26s | 44.9 → **48.6** | 128.4 → **87.2** ms | 2.66 → **2.5** ms | 11.2 → 9.5M |
| v8m → 26m | 50.2 → **53.1** | 234.7 → **220.0** ms | 5.86 → **4.7** ms | 25.9 → 20.4M |
- v8s에서 26s는 Tensor 성능이 26버전이 더 부족하다.
- Flops : 컴퓨터의 float 연산 횟수
	- **FLOP** = 부동소수점 연산 **1회**
	- **FLOPs** = 부동소수점 연산의 **횟수**
	- **FLOPS** = 초당 부동소수점 연산 횟수

Yolo26s의 장점
- 같은 크기에서 더 정확함
- NMS를 모델 자체에 포함함
- 양자화 병목이 적다
- 작은 객체를 위한 의도적 설계가 많다.
- Python 전환 비용이 더 낮다

HailMary 프로젝트에서 Yolo26s를 선택한 이유
1. s 모델이 8버전보다 가볍다.
