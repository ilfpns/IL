AI 요소 class는 4개의 public method를 가지도록 설계했다.

1. init
2. connect 
3. process : AI 판정
4. result : 다음 element의 src (판단 로직에 사용)

	- AI가 영상을 넘기는 경우
		1. 애매함
		2. 추론 실패

Camera element와 AI element는 요소 단위로, 두 요소는 pad로 이어진다. 
- Pad : 두 요소의 입출력이 이어진 연결점 
	- Sink pad : 데이터를 받는 입구
	- Src Pad : 데이터를 내보내는 출구

- Probe : Pad를 통해 데이터가 지나갈 때 중간에서 관찰하거나 개입할 수 있는 객체
```
GstPad *pad = gst_element_get_static_pad(identity, "src");

gst_pad_add_probe(
    pad,
    GST_PAD_PROBE_TYPE_BUFFER,
    aiProbe,
    this,
    nullptr
);
```
identity는 AI element이다. 그러므로 src라 칭하는 ai element의 pad를 probe이 buffer를 관찰한다. 
probe은 Gst가 Buffer를 ai element의 pad로 보내어 값을 전달할때 Probe을 호출한다.
이는 GST_PAD_PROBE_TYPE_BUFFER 이 매크로가 처리한다. Buffer 안에 값의 이동을 관찰하는 것이다.

---

```
GstPad *pad = gst_element_get_static_pad(identity, "src");  
gst_pad_add_probe(pad, GST_PAD_PROBE_TYPE_BUFFER, aiProbe, this, nullptr);  
gst_object_unref(pad);
```
Pad는 왜 요소를 얻자마자 반환할까? GstElement는 계속 멤버로 들고 있는데,,

핵심은 소유권과 참조의 목적이 다르기 떄문이다. 
프로젝트에서 Pad는 Probe의 등록을 위해서 잠시 가져온 핸들이다. Probe을 등록하면 Pad pointer를 사용할 필요가 없으므로, 획득한 주소를 다시 반납한다.

만면 Identity (AI element)는 왜 반납하지 않을까? 
그 까닭은 Identity는 계속해서 사용하는 요소이기 떄문이다.

gst_object_unref는 요소 삭제가 아닌 reference 하나 반납을 의미한다. Identity는 ai element의 소유, Pad는 Probe을 위한 핸들러 참조 차이이다.
