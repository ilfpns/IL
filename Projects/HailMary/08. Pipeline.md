Pipeline 핵심은 다음과 같다
```
Purpose -> Src/Sink -> data define -> devide element -> connect 
```

전체 흐름 구상을 위해서 가장 큰 대략적인 흐름을 잡는다. 대략적인 흐름은 다음과 같은 것이다.

1. Camera에서 OpenCV를 통한 영상 받아오기
2. Yolov8에서 영상 속 객체 BBox 
3. 문제 객체 탐지 시 영상 백업 준비 (다른 분기로 이동)
	1. 문제 없을 경우 다시 1번

여기서 Element를 얼마나 세세하게 나눌 것인지가 중요하다

---

Element는 크게 다음 3가지를 위해서 나누어 사용한다.
- 재사용성
- 유지보수성
- 병렬 처리 구조

독립적인 데이터 처리 역할을 하며, 교체나 재사용이 가능하게 제작해야 한다. 이는 너무 잘게 쪼갠 Element가 overhead로 성능 저하를 야기하지 않도록 관리해야 한다.

----

Caps(Capabilities)는 pad가 주고받을 수 있는 미디어 데이터의 형식을 구조화한 것이다. 
=> 데이터가 어떤 형식인지 정의하는 미디어 데이터 규격 정보

카메라 영상은 다음과 같은 정보를 보여줄 것이다.
```
video/x-raw,
format=RGB,
width=1920,
height=1080,
framerate=30/1
```

Gst의 element는 아무 데이터나 주고받지 않고, 서로 처리 가능한 데이터일 때 연결이 가능하다. 그러므로 Caps의 규격을 보고 갹 Element 사이에 Convert or Decode를 넣어야 한다.

이러한 Caps까지 고려하여 위 4단계 흐름을 더 세분화 해보자.
