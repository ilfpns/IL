PITH 프로젝트에서 UART TX/RX를 구현하였다. 실제로 이를 flash하고 uart 입력을 확인했을때 TX는 잘 동작하는 상황이다. 하지만 RX가 동작하지 않으며, RX를 디버깅 해야 하는 상황이다. 

- TX : 버튼을 누를 경우 TX로 문구 출력
- RX : 사용자가 입력한 문자열을 그대로 다시 출력 ← 동작 안 함

            ⇒ 하드웨어 디버깅 인터페이스
                
                
                먼저 표준은 두 분류로 나뉜다.
                
                - JTAG
                    - Joint Test Action Group
                    - 펌웨어에 break문을 걸어가며, 변수에 값이 잘 쓰여지는지, 구문이 잘 싱행되는지 테스트한다. 이 자체로 디버깅 역할을 하며, bin파일을 flash하거나 읽어올 수 있다.
                    - 많은 PIN을 사용하는 HW 장치인 것이 단점이다.
                    - IEEE에서 만듦
                - SWD
                    - Serial Wire Debug
                    - 시리얼로 통신하기 때문에, 클럭 (SWCLK)와 데이터 (SWDIO) 2개의 핀만 사용한다. Break Point 지정으로 펌웨어 디버깅을 진행한다.
                    - ARM이 만듦
                
                두 하드웨어 디버깅 인터페이스는 Boundary scan에 있다. JTAG만이 해당 기능을 지원한다.
                PCB에 연결된 IC 상태를 점검할 수 있으며, 그 밖에도 다음과 같은 역할을 수행할 수 있다.
                
                - IC의 입출력 핀 상태 확인
                - PCB 연결 상태 검사
                - 납땜 불량이나 단선 검사
            
            ST-Link는 PC와 하드웨어 디버깅 인터페이스 (SWD, JTAG) 사이에서 동작하는 장치으로, 다음과 같은 역할을 수행한다.
            
            - MCU에 펌웨어 다운로드
            - Breakpoint 및 Step 디버깅 지원
            - MCU 레지스터와 메모리 접근
            - 디버깅 통신 중계
            
            ST-Link는 PC가 작성한 명령을 MCU가 해석 가능하게, 이해 가능한 하드웨어 통신으로 잇는 장치이다.

- 해결
    
    일단 지금 임시 방편으로 해결했다….
    
    바로 다른 보드를 사용한 것, 물론 지금 보드가 flash가 안 되는 것도 디버깅하여 해결할 것이다.
    
    새 보드에 flash를 하며 겪은 것을 따로 정리하려 한다. 
    일단 RX는 문제가 아니었다. 이전을 보면 알겠지만 그냥 flash 자체가 안 된 것이지, rx 문제가 아니었다.
    
    해결 흐름은 다음과 같다.
    
    - flow
        1. 부팅 시 바로 hardfault 발생 문제
            - explain
                
                Hardfault 호출이 svc보다 먼저 와서 발생한 문제이다.
                
                ⇒ SVC 실행 위치가 문제였다. 첫 task가 실행되고, PSP에 task stack address가 잡혀야 하는데, 그렇지 않게되고, CPU는 엉뚱한 메모리에 접근하고, Busfault가 발생하며 Hardfault로 이어지는 것이다. 
                
                Task 생성 이후 Hardfault 설정 전에 svc를 먼저 호출하여 task stack address를 연결하여 문제를 해결했다. 
                
        2. IWDG전에 PR/RLR 초기화 문제
            - explain
                1. LSI 공급 (저속 클럭 공급으로 IWDG의 독립적인 클럭 공급)
                2. 기존에 IWDG를 사용할때 CMSIS를 사용하여 IWDG 세팅을 변경했다. 
                
                <img width="631" height="227" alt="스크린샷 2026-11-17 오후 9 50 22" src="https://github.com/user-attachments/assets/4f34a650-f7cf-4c03-b7f5-4fc130b49485" />                
                처음 KR이후 레지스터 접근을 허용한다. (0x5555) 이후 분주 설정과 PR (분주/카운트 속도), RLR (리로드/시작 값)을 정한다. 그 후 SR로 설정 Flag를 사용한다.
                
                여기서 PR과 RLR이 적용되기 전에 다음 동작을 시작해서 오류가 발생하는 문제가 있었다. 그렇기 때문에 SR flag 설정을 확인하며 busy waiting을 진행했다.
                
        3. LED 점멸 주기 문제
            - expalin
                
                task1과 task2가 주기/위상이 같아서 on → off → on 이 빠르게 이뤄짐
                
                ⇒ task2의 루프 시작 전 task1의 delay만큼을 추가로 넣었다.
                
        4. Reset IWDG 문제
            - explain
                
                이전에 사용하던 alive_report와 kick 시간이 맞춰지지 않아서 발생한 문제이다.
                
                ⇒ task의 dealy를 수정하며, 발생한 문제로써, 문제 tick 임계치인 `STANDARD_LINE_IWDG` 값을 늘려 해결했다.
