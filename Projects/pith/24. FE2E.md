### 배운 것

먼저 여러 기본적인 펌웨어에서 개발해야 하는 것들을 배웠다. 

- 기본적인 클럭 설정
- EXTI 설정
- ASM을 활용한 task 전환 + interrupt 처리
- ISR 설계
- 직접 TCB를 사용하는 Task 설계
- RR + Priority 스케줄러 구현
- CS를 위한 Mutex 개발
- Usart TX/RX + 링버퍼 구조 설계
- IWDG 개발 + hardfault
- 디버깅 (OpenOCD + GDB)

이러한 것들을 개발하며, 많은 디버깅까지 했기에,,, 많은 것을 배운 프로젝트 같다. 

먼저 이 프로젝트는 일반적인 라이브러리와 프레임워크, IDE 까지 사용하지 않고 순수 개발 실력을 증진하고 싶어서 시작하였다. 직접 레지스터들을 컨트롤하고, 직접 디버깅 로그를 까보며 심지어는 build와 flash까지 따로 쉘 명령어를 통해 진행했다.

물론 중간에 AI가 코드를 짜고, 내가 컨펌을 하고, 구조를 의논하는 방향으로 빠진 부분도 있었지만, 절대 AI에게 프로젝트를 맡겼다고 생각하지 않는다. 

각각의 구현들을 추상화해서 위에 적어두었는데, 각각 개발하며 재밌었던 포인트, 처음 알게된 포인트들을 조금씩 적어보려 한다. 

가장 먼저 클럭이다. 클럭 자체는 크게 재밌는 건 없었는데, PLL이나 Prescaler 등을 다시 복습하며 직접 내가 HSI를 구현하는 것이 재밌었다. HSE까지 써서 크리스털을 써보면 좋았겠지만, 크게 달라진 건 없을 것이라고 생각한다. 

다음 EXTI이다. 외부 인터럽트 인풋 관련 개발을 하는 것도 재미있었다. 클럭과 마찬가지로 직접 datasheet를 보며 어떤 레지스터가 어디에 붙어있고, 어떤 비트를 Pending하면 되는건지,, 등 많은 것을 배우며 개발했다. 

EXTI → Interrupt → IRQ → NVIC → ISR 등의 구조를 짜는 것도 재미있었다. 
APB2와 APB1은 결국 주변 장치가 붙어있는 버스를 의미하는데, 속도가 차이난다라는 그런 것들도 배울 수 있어서 좋았다. 

다음으로 ASM handler인데, 이 부분은 내가 직접 ASM을 개발한 것이 아니다보니, 개념상의 Pend, IRQ 등만 이해하고 있다. naked한 함수를 활용한 것을 흥미롭긴 했다.

ISR 설계는 위에서 말한 것처럼 Handler + EXTI 처리 흐름 설계였고, 재밌었다. 

거의 최고로 재밌었던 Task 부분이다. Task는 TCB를 직접 구현하며, 어떤 값들이 저장될지 내가 직접 설계하는 게 아주 짜릿했다. 구조체를 구성하고, 이를 활용하여 task create 함수나, 이후 구현하는 스케줄링으로 사용하는 것, 직접 함수를 연결하여 기능을 수행하는 것은 재밌었다. 

스케줄링 부분은 사실 크게 어렵지 않았다. 개념이 쉬운 두 스케줄링 기법을 합친 것과 이전에 Context Switching을 naked하게 구현해 두었기에, 이를 사용하는 게 전부였다.  

다음은 Mutex인데 이것도 아는 개념을 직접 개발하니 재밌었다. 물론 나중에는 그냥 PRIMASK나 disable_IRQ를 많이 사용했지만, 이 개념 자체를 구현해 본 것은 좋았다. 이걸로 나중에 GDB를 가지고 디버깅도 했으니 만족한다.

Uart에 동기화를 추가한 것, Usart를 구현하는 것도 아는 개념을 더 공부하며 TX/RX를 개발하는 게 흥미로웠고, Overrun이나, 넘치는 값들을 링버처 자료구조로 커버하는 것 역시 나쁘지 않았다. 

Task보다 재밌었던 IWDG 파트이다. 나는 항상 뭔가 펌웨어를 개발할때 문제가 생기면 main으로 return하고 끝나는 구조였는데, 사실 이건 실제 개발물에 쓰이는 구조는 아닌 걸 알고있었다. 
그래서 IWDG를 구현하여, 각 task가 alive report를 진행하고, 가장 늦은 task가 supervisor하며 kick을 진행하는 것, 문제 발생 시 NVIC reset → reboot에서 재부팅에서 원인 task를 찾는 것이 좋았다. 

또한 Exception Handler로 처리 불가한 오류를 Hardfault로 보내고, 리부트하고 해당 원인을 추적하는 것도 좋은 경험이었다.

아마 IWDG와 hardfault 예외 설계는 나중에도 쓸 거 같다.

마지막으로 디버깅이다. openOCD와 GDB를 사용했는데, 이 구졸를 배우는 것 부터 재미있었다. 1학년때부터 알았던 모호했던 SWD/JTAG 개념을 확실하게 잡은 것까지 좋았다.

간략하게 설명하면 PC에서 GDB명령어를 입력하면 openOCD가 이를 STM32가 이해할 수 있도록 변환한다. 이후 ST-Link를 타고 들어가서 SWD나 JTAG로 명령어가 전달된다. SWD나 JTAG는 하드웨어 디버깅 인터페이스로, OpenOCD로 변환된 GDB 명령어가 통신하는 규격대로 개발된 하드웨어이다.  

이러한 구조를 배우고, 직접 break point를 걸고 program counter (PC)를 까보면서 디버깅 하는 것 역시 처음이었기에 재밌었다. 

mutex_lock에서 hardfault까지 발생시키며, bt (back trace)를 활용하여 추적하는 것도 좋았다.

이번 프로젝트는 생각보다 재밌게 진행했다. 예전에 뵈었던 임베디드 개발자분이 개발하는 방식을 보고, 흥미를 느껴 시작했는데, 이렇게 만족스럽게 할 줄 몰랐다.
