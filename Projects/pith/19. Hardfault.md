이제 원하는 기능 개발은 마쳤고, 개발한 코드를 다듬어서 더욱 고도화 하는 것을 목표로 잡고있다. 

---

hardfault 이는 exception으로 처리 불가한 경우 발생되는 메시지이다. 위 메시지가 발생할 경우, 복구 불가능한, 시스템 오류로 판단하여 재부팅이 요구된다.

발생 경유는 다양하다.

1. 보구 불가능한 system
2. 원인 파악이 불가능한 메모리
3. 각종 fault로 handler로 처리 불가능한 경우
4. 빈 페이지가 없을 경우 (새 할당 불가)
5. 정해진 수치보다 적을 경우

HardFault가 발생하는 것 자체가 예측 불가하다. 명확한 원인 파악이 어려우며, 이를 추적하기 굉장히 어렵다. 원인을 파악하더라도, 해결하는데 무수한 가능성을 열어 Try해야한다.

개발 단계에서 수많은 디버깅을 통해 조치해야한다. 

---

일반적으로 Hardfault는 두 개념으로 해석 가능하다.

1. hardfault 처리
2. hardfault 상황에 대한 재현

1번의 경우에는 각 PC, LR, xPSR, CFSR, BFAR 같은 폴트 정보와 현재 태스크 이름 등의 정보를 몹고, 이를 비휘발 공간에 저장한다. 보통 2개의 공간으로 나뉜다. linker src의 .noinit 섹션에 보관하거나, STM32F103에 존재하는 백업 레지스터 (BKP)에 저장한다. Flash는 확실한 비휘발 메모리이지만, 비용이 크다. 이후 리부트를 진행하고, 작업 복구까지가 흐름이다. 

Flash는 page 단위로 쓰고, 지워야 하므로, 이 연산 속도와 구현 난이도가 높다.

2번의 경우 hardfault 상황 발생 시 이 상황에 대한 오류 경유 재현을 진행한다. 이는 디버깅 과정에서 실행한다.

---

BKP는 백업 레지스터로, APB2에 포함된다. 

- Advanced Peripheral Bus는 느린 주변 장치가 연결된 버스를 의미한다.
    - APB1 : 36Mhz (느림)
    - APB2 : 72Mhz (빠름)

BKP는 느린 버스를 사용하므로, APB1ENR을 설정해 주어야 한다.

BKP에는 다음과 같은 값을 저장한다. BKP regi setting → write mode on → save regi info 순으로 진행된다. 

- CFSR : 개발자가 사용하는 오류 상세 저장 상태 레지스터이다.
    - Configuable Fault State Register

report에서는 NVIC reset 이후 다시 진행상황을 복구하며, task를 확인한다. reboot 이후에는 다시 올바른 task 복귀를 확인해야한다. 그렇기 때문에 두 매크로를 사용한다.

- MAGIC NUM
    
    상수
    

```c
#define FAULT_MAGIC     0xFA17U
#define FAULT_NO_TASK   0xFFFFU
```

- NO task → task 알 수 없음을 표시하는 상수
- MAGIC → 의도적으로 자연적으로 나오기 힘든 수로 선정하며, 16bit로 선정한다.
    - Handler에서 dr1에 이 상수를 저장한다.
    - MAGIC이 같음을 확인하며, 해당 Hardfault를 개발자가 의도한 Handler에 의해서 발생한 것임을 알 수 있게 한다.
    - regi 한개가 hw적으로 16bit이다. dr1은 dr2 + dr3 (상위 + 하위)와 별개로 존재하는 비트이다. 그러므로 16비트 아무 상수나 상관없다.
