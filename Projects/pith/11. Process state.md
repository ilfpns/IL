기본 Systick만으로는 완벽한 스케줄링을 할 수 없다. 왜냐하면 부트스트랩이 시작됨과 동시에 Task가 실행되고 이때 발생하는 헤드스타트 위상 차이로 발생하는 것이다. 먼저 실행되는 task1이 task2보다 CPU를 덜 선점하게 되며 정확한 비율이 깨진다.

---

그렇다면 어떤 방법을 쓸 수 있을까?
바로 systick을 활용한 os tick을 이용해 특정 시간마다 실행되도록 하는 것이다. os tick과 delay tick을 더하고, 그 delay 동안 스케줄링을 다시 돌린다.

Next task를 다시 찾고, PendSV는 이를 context switching 한다.

여기서 추가되는 개념은 Processs state이다. process는 여러 state가 있다. 
- BLOCK
- READY
- RUNNING
- PREVENT 

각 state에 따른 처리와, 여기서 겪은 문제들에 대해 기술하겠다.

---

먼저 BLOCK 상태이다. 이는 process가 실행되지 못하게 막히는 상태인데, 프로젝트에서는 task delay 부여 시 BLOCK 상태로 들어가 실행을 멈추고, 다른 task가 실행되는 방식으로 쓰여졌다.

다음으로 READY이다. process는 준비되었지만, 아직 CPU를 점유하지는 않는 상태이다. 이 상황에서는 Next task로 선택될 수 있다. 
프로젝트에서 사용되는 RR을 기준으로 현재 task다음으로 바로 오는 READY task가 실행될 것이다.

ReadyTask는 CPU를 사용하며 실행될 때 RUNNING이 된다. 현재 CPU 자원을 사용하며 실행중인 상황이다. 스케줄러는 다음 실행 task를 찾고, 두 경우에 "찾음" 신호를 보낼 것이다.

1. 다음 READY task를 찾음
	- 이 경우에 다음 Task가 실행된다.
2. 이전에 BLOCK 된 Task의 os tick + delay 가 os tick보다 작아져서 BLOCK이 풀리는 상태
	- 이전에 사용하던 Task를 다시 runnning으로 전환하고, 마저 실행한다.

마지막으로 OOM을 위한 Prevent state이다. OOM은 메모리가 부족해서 더 이상 필요한 메모리를 할당할 수 없는 상태이다. 이 경우에 새 Task를 생성할 수 없고, 자원을 할당받지 못한 task는 PREVENT 상태로 들어간다.
