PITH 프로젝트에서 UART TX/RX를 구현하였다. 실제로 이를 flash하고 uart 입력을 확인했을때 TX는 잘 동작하는 상황이다. 하지만 RX가 동작하지 않으며, RX를 디버깅 해야 하는 상황이다. 

- TX : 버튼을 누를 경우 TX로 문구 출력
- RX : 사용자가 입력한 문자열을 그대로 다시 출력 ← 동작 안 함

---

총 6개의 단게로 이를 디버깅 할것이다.

1. Flash 경로 확인 및 SW적 코드 작성 문제
2. 멀티미터
3. 루프백
4. USB-시리얼 변환기
5. 로직 애널라이저 + PuseView
6. SWD 디버거 

⇒ 1 + 6 ⇒ 2 ⇒ 3 ⇒ 4 ⇒ 5 순서로 디버깅을 진행할 것이다.

make이후에 .bin 파일을 정상적으로 STM32F103의 Flash시작 주소인 0x08000000에 제대로 적재하는 것을 볼 수 있다. 

또한 코드 리뷰 AI를 사용한 결과 RX sw코드 자체에도 문제가 없었다. 그러므로 OpenOCD를 사용하여 직접 신호를 봐야한다.

- 확인 과정에서 발견한 이상한 부분
    
    linker 스크립트를 확인하여, 제대로 된 위치에 Flash를 하는 것을 확인하고, openOCD를 준비하며, TX동작을 기록하려고 하던중, 현재 동작하는 펌웨어의 버전이 굉장히 낮은 버전인 것을 확인함.
    
    ```c
    st-info --probe // usb probe 확인
    ls /dev/cu.*
    screen [probe 정보] 115200 (baudrate) 
    
    /**
    - Stlink
     => ST사의 SW디버거 + 프로그래머
       - FLash 장치
       - 디버깅
       - breakpoint 선정
       - SW 디버깅
    **/
    ```
    
    계속해서 예전 펌웨어가 올라가고, 새로운 bin flash가 막힌 까닭은 다음과 같은 것이라는 가설을 세운다.
    
    1. 현재 보드 자체가 Write 모드가 꺼져있다.
        - 점퍼가 빠진 상황 등
        
        ⇒ Nucleo 보드에서 STM과 ST-link를 잇는 SWD 신호선 중간에 CN2가 있기 때문에, 해당 점퍼를 확인하였고, 두 점퍼가 잘 연결되어 있음을 확인하였다.
        
    2. 보드 위 SWD 선 문제
        - SWD(Serial Wire Debug)은 MCU의 펌웨어 업로드를 실시간으로 디버깅하기 위해 존재하는 2가닥 통신 인터페이스이다.
        - 즉, 디버깅 통신 전점과 규칙을 의미한다.
        
        ```c
        st-info --probe
        
        =>
        ...
        2026-11-16T23:41:47 DEBUG chipid.c: option_base 0x0
        2026-11-16T23:41:47 DEBUG chipid.c: option_size 0x0
        2026-11-16T23:41:47 DEBUG chipid.c: flags 0
        
        2026-11-16T23:41:47 DEBUG chipid.c: otp_base 0
        
        2026-11-16T23:41:47 DEBUG chipid.c: otp_size 0
        
          dev-type:   unknown
        2026-11-16T23:41:47 DEBUG common_legacy.c: *** reading target voltage
        2026-11-16T23:41:47 DEBUG usb.c: target voltage factor=000005ef reading=00000817
        2026-11-16T23:41:47 DEBUG common_legacy.c: target voltage = 3272mV
          voltage:    3272 mV
        2026-11-16T23:41:47 DEBUG common_legacy.c: *** stlink_close ***
        ```
        
        - stlink가 close되어, 접속할 수 없는 상태
        - 위 명령어를 통하여 연결된 stlink의 정보르 확인하였지만, 버전과 전압을 잘 읽어내는데, SWD 접속과 칩 ID를 읽는 데에 실패했다.
        - 예전에 설정한 보드로써 St-link의 버전이 낮을 수 있기 때문에 이를 업데이트하고 다시 진행한다.
        - STSW-LINK007 을 따로 다운받고, St 버전을 업데이트했지만, 버그를 해결하지는 못했다.
