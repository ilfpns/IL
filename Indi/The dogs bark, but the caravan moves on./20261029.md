- [ ]  CS 1h — [임베] 인터럽트
    - 소주제: 처리 흐름(벡터 테이블 → 컨텍스트 저장 → ISR → 복귀), 폴링 vs 인터럽트, ISR 작성 원칙, 우선순위·중첩(NVIC)
        - Study
            
            Interrupt는 갑자기 발생하는 외부 이벤트를 감지하고, 이에 대응하는 루틴을 실행한다. 하드웨어가 외부에서 발생하는 이벤트를 처리하기 위해서 CPU를 강제로 점유하여 일을 처리하고, 이러한 루틴을 ISR이라고 한다. Interrupt 발생 이후, IRQ에서 ISR을 거쳐 원래 분기까지 돌아오는 흐름을 보자.
            
            가장 먼저 일어나는 사건은 Interrupt 발생이다. IRQ(Interrupt Request)가 발생하면 해당 요청이 NVIC로 넘어가고, 해당 Interrupt의 Pending 비트가 1이 된다. NVIC는 개발자가 직접 설정한 NVIC의 레지스터에 저장된 각 IRQ 우선순위에 따라 작업을 처리한다. NVIC는 하드웨어적으로 일을 처리하며, 특정 IRQ를 NVIC에서 disable하면 해당 ISR은 실행되지 않지만, 설정된 우선순위 값은 그대로 유지된다.
            
            - NVIC
            Nested Vectored Interrupt Controller라는 이름으로, 이름 그대로 중첩 인터럽트 컨트롤러이다. 높은 우선순위에 따라(Nested) 다른 Interrupt를 선점할 수 있고, Vector에 따라 vector table에 하드웨어적으로 접근하여 핸들러 주소를 찾아내기 때문에, SW단에서 Interrupt 발생 위치를 찾을 필요가 없다.
            Reset/HardFault 등의 긴급한 Interrupt가 아닌 대부분의 경우는 전부 개발자가 IRQ에 우선순위를 직접 매기며, NVIC는 이에 따라 처리할 뿐이다. NVIC는 현재 CPU에서 돌아가는 ISR과 우선순위를 비교하고, 선점할지 pending으로 처리할지 결정한다. 이후 결정에 따라 CPU에게 Interrupt를 넘긴다.
            하지만 NVIC가 동적으로 우선순위를 매기고 처리하는 일은 없다.
            
            선점이 결정되면 하드웨어는 Handler를 찾기 위해 Vector table을 참조하고, 동시에 원래 실행 중이던 코드의 레지스터 값(R0~R3, R12, LR, PC, xPSR)을 스택에 자동으로 저장(stacking)한다. 이후 Handler 모드로 전환되고 ISR이 실행되며, stack으로 MSP를 사용한다. ISR 작업을 마친 후에는 스택에 저장해 두었던 레지스터를 복원(unstacking)하고, 원래 분기로 돌아가 다시 원래 작업을 수행한다.
            
    - 대표 질문: 인터럽트가 발생하면 어떤 순서로 처리되나? 폴링과 차이는?
    - 복습: volatile·static 대표 질문에 1분 안에 답하기
        - Answer
            
            컴파일러는 코드 안에서 변경하지 않는 변수에 대한 최적화를 진행한다. 이에따라 바뀐 값을 다시 확인하지 않고 명령을 실행한다.그렇기 떼문에 바뀐 값에 맞게 진행되어야 하는 코드가 그렇지 못하게 진행된다. 인터럽트로 바뀐 변수 값이 적용되지 못하는 것이 이에 해당한다. 그렇기 때문에 volatile키워드를 사용하여 변수를 사용할때마다 메모리에서 다시 읽고, 쓰기를 진행하도록 하는 키워드가 volatile이다. 
            
            static 키워드는 크게 2가지 역할을 수행한다. 전역 변수에 static을 사용할 경우 링키지 파일을 변경하여 다른 파일에서 접근이 불가하도록 하는 역할을 한다. 또한 지역 변수에서 이를 사용 시 지역 변수가 위치함 함수가 종료되어도 메모리에서 해제되지 않고, 값이 남아있다. 그러므로 static 키워드를 포함하는 지역변수는 stack에 메모리가 잡히지  않고 data 영역에 잡히게 된다.
