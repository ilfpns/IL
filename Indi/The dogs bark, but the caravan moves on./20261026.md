        - 답변
            
            프로세스는 OS로부터 독립된 주소 공간과 자원을 할당받은 단위이고, 스레드는 그 프로세스 안에서 CPU 스케줄링을 받아 실제로 코드를 실행하는 흐름입니다.
            
            같은 프로세스의 스레드들은 Code, Data, Heap을 공유하고, 각자 스택과 PC·SP 같은 레지스터만 따로 가집니다. 스택을 따로 가지는 이유는 스택이 함수 호출 순서를 LIFO로 기록하는 구조이기 때문입니다. 스레드마다 독립적으로 함수를 호출하고 반환하니, 하나의 스택을 공유하면 다른 스레드의 프레임을 pop해서 엉뚱한 복귀 주소로 돌아가게 됩니다. 반면 힙과 전역 변수는 호출 순서와 무관하게 접근하는 데이터라 공유가 가능하고, 대신 동기화가 필요합니다.
            
            이 구조 때문에 멀티 스레드는 생성과 문맥 교환이 가볍고 데이터 공유가 쉽지만, race condition 위험이 있고 한 스레드의 오류가 프로세스 전체에 영향을 줍니다. 멀티 프로세스는 반대로 무겁고 IPC가 필요하지만 격리가 됩니다. 그래서 Chrome처럼 안정성과 보안이 중요하면 멀티 프로세스를, 데이터 공유와 응답성이 중요하면 멀티 스레드를 선택합니다.

        - Process
            - Process : 현재 실행중인 프로그램
                
                앱은 디스크 (ROM)에 저장된다. 이는 프로그램이다. Process는 ROM에 있는 프로그램이 RAM에 올라오며, 실행 상태로 바뀐 것을 Process라 한다.
                
                Process마다 각 메모리 영역을 새로 할당한다. 하나의 Process에는 각각의 메모리 영역이 따로 존재한다.
                
                - Code : 실행할 기계 명령어
                    - txt : 실행할 기계적 명령어
                    - rodata : 읽기 전용 데이터 (리터럴 상수)
                - Data : 전역 변수, 정적 변수 (Static)
                    - data : 초기값이 있는 정적 변수, 전역 변수
                    - bss : 초기값이 없거나, 0인 정적 변수, 전역 변수
                - Heap : 동적 메모리 (malloc, new)
                    - 개발자가 프로그램을 개발하며 Process 상태일때 동적으로 할당받을 수 있는 메모리이다.
                    - 개발자가 직접 관리한다.
                - Stack : 함수 호출, 지역 변수, 반환 정보
                
                OS는 Process를 직접 관리하기 위해서 PCB를 따로 가진다.
                
            - Process Control Block : OS가 Process를 관리하기 위해 존재하며, 이는 Process의 여러 정보를 저장한다.
                - PID (프로세스 ID)
                - 현재 상태
                    - Process는 State가 5개로 나뉜다.
                        - **New**: 생성 중
                        - **Ready**: 실행할 준비는 됐고 CPU를 기다리는 중
                        - **Running**: CPU를 받아 실행 중
                        - **Waiting(Blocked)**: I/O 완료 같은 이벤트를 기다리는 중
                            - Process가 처리되는 경우 두 병목이 생길 수 있다.
                                - CPU bound : 연산 과정에서 시간이 길어지며 병목 발생
                                - I/O bound : I/O 장치 관련 문제를 처리하며 병목 발생
                        - **Terminated**: 종료
                - PC(Program Counter)와 레지스터 값
                - 메모리 관리 정보: 페이지 테이블 등
                    - Process가 할당받은 가상주소와 실제 피지컬 주소의 매핑 정보를 나타낸 Table
                - 열린 파일 목록 (파일 디스크립터)
                - 스케줄링 정보: 우선순위 등
            
            현재 Process에서 다음 Process로 넘어갈 때 PCB에 현재 상태를 저장하고, 다음 프로그램을 ROM에서 RAM으로 올리며, 이를 실행한다. 이를 Context Swtiching이라고 한다.
            
        - Thread
            
            Thread : Process안에서 실제로 코드를 실행하는 흐름이다.
            
            Process안에서 직접적으로 명령을 실행하는 주체이다. Process는 최소 하나의 Thread를 보유한다.
            Thread 역시 Process처럼 정보를 저장하는 Block이 따로 존재한다.
            
            - Thread Control Block
                - TID: 스레드 ID
                - PC: 지금 어느 명령어를 실행 중인지
                - 레지스터 집합: 연산 중인 값들
                - 스택: 자기만의 함수 호출 기록과 지역 변수
                    - Thread는 메모리 영역 중 유일하게 Stack을 개인적으로 소유한다.
                        - 앞서 Thread는 Process를 이루며, 하나의 실질적인 명령어 실행 단위라고 하였다. 그렇기에 각 Thread는 서로 다른 함수를 호출하고, 서로 다른 지역 변수에 접근할 것이다. 
                        Thread가 함수를 호출하고, 다시 원래 분기로 돌아갈때 Stack에 담아뒀던 주소로 돌아갈 것이다. 이러한 정보를 따로 담아야 하기 때문에 Thread는 개인 Stack을 가진다.
                        Thread가 Stack을 공유할 시 각 Thread 간 분기가 꼬일 수 있다.
                            
                            
                            그렇다고 각 Stack이 완전히 격리된 개념은 아니다. 다른 Thread가 주소를 넘겨줄 시 서로 접근이 가능하다. 
                            
                        - 함수가 역할을 마치고 돌아갈때 Stack에 저장한 주소를 보고 이동한다. 그렇기 때문에 Thread는 Stack말고도 개인 Register를 가진다.
                    - SP (stack pointer), CP (counter program) 등
                - 상태: Ready, Running, Waiting 등
            
            CPU 스케줄러가 실제로 스케줄링하는 대상은 Thread이다. 멀티코어 환경에서 하나의 Process의 Thread가 각 코어에서 실행될 수 있다.
            
            Thread는 각 개인의 Stack은 가지지만, 다른 데이터 영역은 Process의 것을 공통적으로 사용한다. 그렇기 때문에 전역 변수나 정적 변수 값에 동시 접근 시 동기화 문제가 발생할 수 있다. 그러므로 Mutex, Semaphore, TAS, Monitor 등의 방법을 따로 마련해야한다.
            
            - 커널 수준 스레드: OS 커널이 직접 알고 스케줄링하는 스레드. 리눅스의 pthread가 여기에 해당한다.
            - 사용자 수준 스레드: 라이브러리가 사용자 공간에서 관리하고 커널은 모르는 스레드이다. 전환은 빠르지만 하나가 블로킹되면 전체가 멈출 수 있다.
        - Multi Process & Multi Thread
            - Multi Process : 여러 서로다른 Process가 존재함
                - 각기 다른 메모리 영역을 가짐
                - Context Switching 비용이 무겁다.
                - 각 Process 통신에는 IPC가 필요하다.
                    - IPC : Inter Process Communication으로 Process 간 데이터를 주고 받는 방시이다.
                        - Pipe, Message queue, Share memory, socket 등 다양한 방법이 존재한다.
                        - 보통 커널단을 이용하기 때문에, 각 Process는 system call을 사용한다.
                            - mmap : 특정 데이터를 본인 Process의 가상 주소에 매핑하는 System call
                        
                - 하나의 Process가 문제가 생겨도 다른 Process는 안전하다.
            - Multi Thread : 하나의 Process안에서 여러 Thread가 동작함
                - 메모리나 Context Switcing의 Overhead가 적다.
                - 공유 데이터 영역에서 데아터 전달이 쉽다.
                - 하나의 Thread오류가 전체 Thread에 영향을 준다.

        각 Thread는 개인 Register를 가진다. 
        
        - R0 ~ R12 : 범용 레지스터이다. 일반적으로 데이터 임시 저장 장치로 사용한다.
            - 0 ~ 7 : Low Register
            - 8 ~ 12 : High Register
            - Thumb 명령어는 일반적으로 Low Register만을 사용한다.
        - R13 / SP (stack pointer) : Stack에 가장 마지막에 들어간 / top을 가리키는 Register이다.
            - MSP (Main Stack Pointer) : 리셋 이후 기본으로 사용하는 Stack으로 Interrupt/Exception Handler는 전부 MSP에서 처리한다. 리셋 시 벡터 테이블의 첫 번째 값이 MSP값으로 로드된다.
            - PSP (Process Stack Pointer) : 일반 코드 (Thread)가 사용하는 Stack이다. RTOS의 task는 PSP의 stack을 사용한다.
        - R14 / LR (Linker Register) : 함수가 돌아갈 주소를 저장한다.
            - 여러 함수의  복귀 지점을 기억할 수 있도록 stack을 사용한다. 함수 종료 후 각 분기로 알맞게 pop() 연산을 진행하며 돌아갈 수 있다.
            - 예외 인터럽트는 EXC_RETURN라는 특수 값을 받아. 예외 처리임을 인지한다. 예외 핸들러가 종료되고, HW는 알아서 예외를 처리한다.
                - Interrupt 발생 시 이는 ISR예 따라 등록된 Handler (Callback)으로 처리된다.
        - R15 / PC (Program Counter) : 다음에 실행할 명령어의 주소를 저장한다.리셋 시 벡터 테이블의 두 번쨰 갑이 PC로 채워진다.
        - xPSR : 프로그램 상태 레지스터
            - APSR (Application PSR): 연산 결과 플래그
                - N: 결과가 음수
                - Z: 결과가 0
                - C: 캐리(자리올림) 발생
                - V: 부호 있는 오버플로 발생
                - Q: 포화 연산에서 포화 발생
            - IPSR (Interrupt PSR) : 지금 처리 중인 예외 번호. 0이면 일반 코드(Thread 모드), 0이 아니면 핸들러 안이라는 뜻이다. 예를 들어 SysTick이면 Interrupt code가 15이다.
            - EPSR (Execution PSR) : 명령어 실행 상태를 저장한다. T 비트(Thumb)가 항상 1이여야 한다. 만약 0일 경우 HardFault가 발생한다.
