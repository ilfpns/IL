        - Study
            
            메모리 영역이란 프로그램 실행에 필요한 명령어와 데이터를 저장하는 메모리의 공간이다. 이 메모리 공간은 보통 여러개로 나뉜다. 메모리 영역은 왜 나뉠까? 그 까닭은 데이터마다 수명과 특성이 다르기 때문이다. 그렇기에 서로 다른 수명과 특성을 보관하는 영역을 나눈다.
            
            Code → Data → Heap → Stack 순서로 배치된다.
            
            1. Code 
                - 실행될 프로그램 명령어가 저장되는 영역이다.
                - 프로그램 시작부터 끝까지 저장되며, 실행 중 수정이 불가하다.
            2. Data
                - 전역 변수와 정적 변수가 저장된다.
                - 프로그램 시작부터 끝까지 저장되며, 어느 위치에서나 접근할 수 있다.
                    - data : 초기 값이 있는 전역 변수, 정적 변수
                    - bss : 초기 값이 없거나 0인 변수
            3. Heap
                - 실행하기 전에 영역이 잡히지 않고, 개발자가 의도한 대로 메모리가 할당된다.
                - 개발자가 직접 할당하는 영역이다.
                - 개발자가 동적으로 (malloc)할당 할 수 있으며, 메모리 해제를 해주어야 한다.
                    - Heap의 사용은 여러 문제를 야기할 수 있다.
                        - 단편화
                        - 장시간 운용
                            - 재부팅 없이 장기간 운용 시 누수 발생 위험
                        - 실패 대처의 어려움
                        - 실시간성 보장 불가
            4. Stack
                - 함수가 실행될때 필요한 정보들을 저장한다.
                    - 저장: 지역변수, 매개변수, 함수가 끝나고 돌아갈 복귀 주소
                    - 수명: 함수가 호출될 때 생기고 리턴하면 사라진다.
                    - 관리: 컴파일러가 자동으로 합니다. 프로그래머가 해제할 필요가 없다.
                
                함수 호출 시 스택 프레임이 Stack에 쌓인다. Stack Frame은 Stack에서 사용하는 덩어리 단위이다. 이떄 가장 top의 주소는 SP에 저장된다. SP는 첫 주소로부터 주소를 더해가며 다음 stack 위치로 이동하기 때문에 빠른 연산이 가능하다.
                
                Stack에서 PoP이 발생할때 SP는 값이 바뀌지만, 실제 stack에 있던 하나의 stack frame 데이터를 삭제되지 않는다. 그렇기 때문에 초기화 되지 않은 변수에서 쓰레기 값이 나오는 이때문이다. 새롭게 호출된 함수가 예전에 다른 함수가 사용한 자리에 위치하고, 함수 내 지역 변수가 이전 쓰레기 값을 할당 받는 것이다.
                
                Stack은 정해진 크기만큼 사용할 수 있다. 이 크기를 넘을 경우에는 Stack overflow가 발생하고, 이 데이터가 근처 Heap, Data를 침범할 수 있다.
                
                - buffer Canary : buffer가 지정된 크기보다 클 경우, 정해진 크기 밖의 데이터가 망가지는 것을 감지하고, 이를 비정상 종료 처리를 진행함.
                    - 값을 비교하여 값이 바뀌었는지 감지함.
    - 대표 질문: 전역·지역·static 변수는 각각 어디에 저장되나?
        - 답변
            
            전역변수와 static 변수는 Data 영역에 저장됩니다. Data 영역은 다시 0이 아닌 값으로 초기화된 변수가 들어가는 data 섹션과, 초기값이 없거나 0인 변수가 들어가는 bss 섹션으로 나뉩니다. 이 변수들은 프로그램이 끝날 때까지 유지됩니다.
            
            함수 안에서 선언한 static 변수도 Data 영역에 저장되기 때문에, 접근은 그 함수 안에서만 가능하지만 함수가 끝나도 값이 유지됩니다.
            
            지역변수는 Stack 영역에 저장되며, 함수가 호출될 때 생성되고 함수가 끝나면 스택 프레임과 함께 자동으로 해제됩니다.

        Board를 제어하기 위해서 Low수준으로 갈수록 ASM을 활용할 일이 많다. Context Switching을 담당하는 PendSV같은 Callback을 활용하기 위해서는 Naeked함수를 개발해야한다. 
        
        - Thumb : 16bits ASM으로 ARM에 비해 상대적으로 작고, 비교적 적은 명령어를 지원한다.
            - Thumb방식으로 인코딩을 진행한다.
            - ARM cortex m 시리즈는 Thumb 명령어만을 지원한다
        - ARM : 32bits ASM으로 Thumb에 비해 상대적으로 크고, 다양한 명령어를 지원한다.
            - ARM방식으로 인코딩을 진행한다.
            - AAPCS (Procedure Call Standard for ARM architecture)는 ARM에서 명령어를 사용하는 방식을 정의한 것이다.
                - r0 ~ r3에 함수 전달 인자를 저장한다. r3가 최대이므로 함수 인자가 4이상일 경우 Stack Memory로 저장된다.
                - 함수 반환값은 어떤 Register에 저장할지 결정한다.
                - 함수 종료 이후 LR (함수 종료 후 어느 원래분기로 돌아갈 주소를 저장하는 Register)에 어떤 방식으로 주소를 적재할지 결정한다.
        
        두 모드는 서로 다른 모드로, 다르 모드 전환 시 State switch가 필요하다.
        
        과거 보드에 자원이 소중하던 시절에는 Thumb가 ARM보다 가벼웠기에 훨씬 이득이었다. 하지만 이는 ARM보다 근본적으로 사용 가능한 bit수가 적고, 기능이 부족했다. 그렇기에 과거 ARM architecture는 ARM모드와 Thumb모드를 전환하며 사용했고, 서로 다른 인코딩 방식으로 Overhead가 있었다. 그렇기 떄문에 이를 보완하기 위해서 32bit를 지원하며, Thumb방식 인코딩을 지원하는 Thumb2가 등장한다.
        
        ARM방식과 Thumb방식을 혼합하였기 때문에 ARM의 속도를 보이며, Thumb의 크기를 가진다.

            | `SUB R0, R1, R2` | R1의 값에서 R2의 값을 빼 R0에 대입한다. |
            | `MUL R0, R1, R2` | R1과 R2의 값을 곱해 R0에 대입한다. |

        - Startup / Bootloader / Bootstrap
            - Startup : 초기화 또는 코드 시작 과정으로, 프로그램 실행에 필요한 메모리와 환경을 준비한다.
            - Bootloader : 부팅 프로그램으로, 다음 단계의 process나 OS를 실행한다.
            - Bootstrap : Bootloader가 시작할 환경을 만드는 것으로, 시스템이 스스로 실행 가능한 환경을 만든다.
            
            일반 데스크톱의 경우 Bootstrap으로 실행 환경 및 HW를 준비하고, Bootloader로 OS를 올린다. 그 후 Startup으로 프로그램을 실행할 준비를 한다.
            
        
        Startup Code : HW초기화 시 가장 먼저 실행되는 SW로, 다음 실행 코드를 준비하며, 주로 ASM이나 저수준 C언어로 작성된다.
        HW초기화 이후에 0x00000000의 값을 MSP에 넣고, 0x00000004를 PSP에 넣는다. Vector Table의 앞 두 자리는 위 두 값들이 들어온다. 이후 다른 코드들이 실행된다. 
        
        F103 ASM을 기준으로 흐름은 다음과 같다.
        
        1. `.isr_vector` 섹션 정의: 첫 칸 `_estack`, 둘째 칸 `Reset_Handler`, 나머지 예외·IRQ 핸들러(weak으로 `Default_Handler`에 연결)
        2. `Reset_Handler`: SP 세팅(하드웨어가 이미 했어도 명시하는 편이 안전)
        3. `.data` 복사 (Flash → RAM)
        4. `.bss` 0 채움
        5. `SystemInit` (클럭, Flash latency)
        6. `__libc_init_array` (해당 시)
        7. `main` 호출 후 무한루프

        - 전원 인가부터 `main()`까지의 흐름을 리셋 시퀀셜이라 한다. 일반적인 리셋 시퀀셜은 다음과 같은 것이다.
            1. Reset 
            2. boot mode 설정
            3. Vector table의 첫 번째 주소를 MSP에 할당
            4. Vector table의 두 번째 주소를 Reset Handler (PC)에 할당한다.
                - 여기서 `0x08000101` 주소를 PC에 담는다고 가정할때 가장 마지막 bit인 1이 Thumb 명령어의 정상 여부를 판단한다.
                - 0이 경우 Hardfault가 발생한다.
            5. Reset Handler가 Startup을 호출한다.
            6. 실행 환경이 초기화된다.
            7. `main()` 이 시작된다.

- [x]  AI 개념 (30분–1h) — [기초] 데이터 → 학습 → 추론 흐름
    - 소주제: 파라미터(가중치), 학습과 추론의 차이, 체크포인트, 학습은 서버 GPU·추론은 엣지
        - Study
            
            학습은 모델을 만드는 과정에서 데이터의 규칙을 파악하며 학습하는 것이고, 추론은 완성된 모델이 예측/판단 결과를 내는 것이다. 지도 학습을 기준으로 AI 학습 시 train data를 여러번 epoch (학습)하며, 규칙을 파악하고, 파라미터를 조정한다. Epoch 횟수는 데이터의 크기, 모델의 크기 등 다양한 요소로 다르게 측정되겠지만, 오랜 시간이 걸리기 때문에 중간 Epoch을 저장하는 Checkpoint가 필요하다.
            
            파라미터란 AI가 데이터를 학습하면서 바뀌는 숫자 값을 의미한다. 데이터의 특징을 학습하며, 수식에 사용되는 값들이 바뀌는데, 이것을 파라미터라 한다. 반대로 개발자가 고정하여 사용하는 값을 하이퍼파라미터라 칭한다. 하이퍼파라미터는 threshold같은 것들이 포함된다.
            
            - threshold
                
                이는 정답의 기준점으로, AI가 추론한 결과물을 정답/오답으로 분류하는 기준이다. threshold값보다 크다면 정답, 작다면 오답과 같은 식으로 처리하는 기준선으로 개발자가 직접 정한다.
                
            
            가중치란 파라미터의 일부로, AI가 학습을 하며, 데이터를 보고 실제 정답과 오차를 줄여나가는 수식에서 나온 파라미터 중 대부분이 가중치이다.
            
            학습에는 대규모 병렬 연산과 높은 메모리 대역폭을 제공하는 GPU가 적합하다. 학습 과정에서는 순전파뿐 아니라 역전파와 파라미터 업데이트를 수행해야 하기 때문이다. 반면 추론에서는 일반적으로 학습된 가중치를 고정한 채 연산하므로, NPU처럼 신경망 연산에 특화되고 전력 효율이 높은 하드웨어가 적합할 수 있다. 특히 NPU는 연산 구조와 메모리 접근을 최적화하여 추론에 필요한 전력과 데이터 이동 비용을 줄일 수 있다.
            
    - 확인 질문: 학습과 추론은 하드웨어 요구가 어떻게 다른가?
        - 학습에는 대규모 병렬처리와 메모리 대역폭을 고려한 GPU가 적합하고, 추론에는 최적화된 신경망 연산과 메모리 접근 구조를 가지며 저전력으로 싱행되는 NPU가 적합하다.
    - 복습: AI 지도
        - Answer
            
            ML과 DL은 모두 AI를 학습시키는 방식이다. ML은 개발자가 데티어의 특징을 설계하며 AI를 만드는 것이고, DL은 원시 데이터를 input으로 사용하여 설계된 AI의 각 Layer가 원시 데이터의 패턴 특징을 스스로 학습하는 것이다.
